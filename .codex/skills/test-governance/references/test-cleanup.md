# Test Cleanup

仅在以下情况读取本文件：

- 出现 `Development`、`Acceptance`、`Regression`、`Reproduction`、`Temporary`、`Migration` 等阶段性测试；
- 怀疑同层重复测试；
- 旧业务行为或旧实现已经退出；
- 测试权威路径出现分裂；
- 用户要求清理或收敛测试。

目标不是减少测试数量，而是让每个长期测试都有明确职责。

## 1. 需要审计的类型

### 重复职责

多个测试处在相同或高度重合的测试层，并验证：

- 相同业务契约；
- 高度相似输入；
- 相同结果；
- 相同失败意义。

这时才优先考虑合并。

### 过期测试

测试保护的行为、协议或实现已经被正式替代，
且不再承担兼容、迁移或防回退职责。

应删除或改写。

### 阶段性测试

开发、调查、reproduction、独立验收或迁移产生的测试，
不能因为当前迭代结束就自动成为长期资产。

### 低价值测试

没有提供稳定契约保护、独立诊断价值或额外风险覆盖，
只是重复实现细节、已有断言或形式覆盖。

不要仅根据覆盖率、文件名、行数、长期不失败或执行时间判断低价值。

## 2. 收口结果

阶段性测试最终只能进入以下状态之一：

### Keep as primary

成为某行为在某测试层最清晰的稳定责任入口。

### Keep as supporting

保护独立实现边界、特殊失败路径或诊断能力，
且与 primary 的失败意义不同。

### Keep as acceptance / gate

证明较低层无法证明的跨层契约、真实环境行为或发布门禁。

### Merge

多个测试在同层保护相同契约，
拆分没有明显导航或诊断价值。

### Delete

测试只用于开发、调查或一次性验收，
且稳定测试已经等价保护该行为。

## 3. 独立验收不等于永久重复

实现测试和独立验收在验收阶段允许暂时覆盖相同场景，
因为产生视角不同。

验收完成后重新判断：

- 哪个更适合作为长期责任入口；
- 是否存在独立测试层价值；
- 是否需要合并断言；
- 是否应删除阶段性测试。

不要因为文件名包含 `Acceptance` 就默认永久保留。

## 4. PowerPoint 示例

如果同时存在：

```text
PowerPointAttachmentParserDevelopmentTest
PowerPointAttachmentParserAcceptanceTest
```

且都覆盖 PPT/PPTX 文本、shape 顺序、OCR、offset 和错误路径：

- 已被 Acceptance 等价覆盖的外部行为：Development 中相同断言优先合并或删除；
- Development 中具有独立诊断价值的 parser 内部边界：保留为 supporting component test；
- 临时开发验证：删除；
- 捕获真实历史 Bug 且没有稳定保护：并入长期 regression protection；
- Acceptance 证明跨层契约或正式门禁：可以长期保留。

## 5. 被替代行为

生产旧机制已经退出时，只服务旧行为的测试也必须重新判断。

只有仍承担以下职责时才保留：

- 兼容性；
- 迁移；
- 防止旧行为重新进入生产路径；
- 其他明确稳定职责。

## 6. 临时清理清单

需要用户审阅时，可以维护短期 `TEST_CLEANUP.md`：

```md
## TC-001 聚合搜索分页职责疑似重复

- 范围：aggregate-search / pagination
- 候选：A、B
- 问题：是否同层重复保护同一 stable pagination 契约尚未确认。
- 建议：比较 Spec、测试层、输入输出和失败意义。
- 状态：待审阅
```

它是工作清单，不是永久技术债档案。

稳定结论应迁回 Test Index、路径规则、Spec 或当前迭代任务；
处理完成后删除对应临时条目。

## 7. 禁止自动清理

不得仅依据以下信息删除测试：

- 文件名相似；
- assertion / 行数相似；
- coverage 重叠；
- 长期没有失败；
- 一个 primary 已经存在。

清理判断必须结合：

- Spec / 契约；
- 测试层；
- 行为语义；
- 输入输出；
- 失败意义；
- 兼容 / 环境职责。
