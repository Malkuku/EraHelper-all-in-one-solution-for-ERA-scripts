# 独立任务配置指南

本指南对应“分步任务”界面。导航沿用原版的规则组选择、API配置、规则组配置、规则编辑、正则测试和额外功能，并提供预设管理与运行结果入口。实际酒馆、酒馆助手、提示词模板扩展及 MVU 的组合版本仍需宿主验收；不要把本文当作已经验证的版本兼容声明。完整接口以[分步任务目标契约](../AI2AI/API/分步任务目标契约.md)为准。

## 从旧版重新配置

旧插件配置不自动迁移。看到“旧版分步配置不受支持”时，需要按下面步骤重新建立连接、预设、任务与规则组，再点击“保存配置”。旧 Profile、跟随酒馆当前连接或预设、旧正文世界书配置及旧事件接口不再使用。

已配置过独立任务版本 1 的数据会保留原运行组合，升级为版本 2 的“API 绑定预设”。同一 API 原来配了多个预设时，会拆成对应的 API 配置，共享原本的本地密钥；未引用的 API 保持未绑定，需要手动选择预设后才能用于任务。保存后使用版本 2，不需要重建已有任务。

新界面的编辑先进入草稿，点击“保存配置”后才生效；保存失败会显示错误，请修正后重试。“撤销未保存修改”会恢复已保存配置。“导入配置”替换当前草稿，导入后仍需保存；“导出配置”导出完整的新配置，包含插件预设副本，但不包含插件连接密钥。

重新配置不会迁移旧连接密钥；请在新连接中重新填写。本模块只清理自己旧配置中的明文密钥与已退出字段，不清空其他模块数据、正文或世界书内容。

## 先建立预设，再绑定 API

按顶部步骤依次准备预设、配置 API 并绑定预设、创建任务、关联规则组、选择活动组并保存。顶部“当前生效”始终显示已保存的规则组，以及每项任务的 API、模型和预设；下方编辑的是草稿，保存前不会改变运行配置。

在“API配置”页点击“新建连接”，填写便于识别的名称、API 根地址及模型。地址是 OpenAI 兼容服务的根地址，例如 `https://example.com/v1`，不要填写完整的 `/chat/completions` 端点。任务只使用自己选择的连接，不跟随主聊天的模型、连接或密钥。

在 API 配置中选择“绑定预设”。一个 API 配置绑定一个预设，任务选 API 即确定模型、提示词和采样设置；修改绑定并保存会影响所有引用此 API 的任务，引用列表可直接打开任务。同一服务需要不同预设时，新建不同 API 配置。可通过“编辑绑定预设”直达编辑器，预设页会列出绑定它的 API。

“测试连接”检查 `/models` 是否可访问；“获取模型列表”显示模型数量并可选择模型，也支持手填。两项都使用当前草稿地址及密钥，留空使用本地已存密钥，已点击清空则使用空值，新填写密钥优先；测试不会保存密钥或草稿。失败显示原因并可重试，请求可取消。服务不支持模型列表时可继续手填模型；模型接口通过不代表生成请求已通过。

“更新本地密钥”用于设置密钥；留空保留已存密钥，“保存时清空密钥”用于明确清空。配置保存成功后才会处理本地密钥变更。密钥保存在当前宿主来源、当前脚本身份对应的浏览器本地存储中；换浏览器、来源或脚本身份后可能需要重新填写。配置与预设导出不能作为密钥备份。连接仍被任务引用时，先修改任务引用再删除连接；删除保存成功后才清理不再使用的本地密钥。

在“预设管理”页使用“导入酒馆原生预设”，选择从酒馆导出的 OpenAI 预设 JSON，并给插件副本命名。同名副本会要求确认覆盖；需要保留旧内容时，先复制副本或使用其他名称导入。酒馆原预设以后发生修改，不会自动同步到插件。

轻量编辑器可修改温度、回复和上下文 Token 预算、常见采样参数，以及提示词内容、角色、启停、顺序和注入位置。回复 Token 必须小于上下文 Token。也可以“新建预设”，按模型能力填写上下文预算，再补充提示词。

提示词启停与排序使用原生全局顺序 `character_id=100001`；其他顺序及未知字段保留在原生副本中。导出原生预设只输出原生 JSON，不把插件记录的 ID 混入其中。复杂结构可在酒馆编辑后重新导入；未知字段被保存不等于插件会执行对应扩展行为。文本任务不支持的工具、图片、音视频或自动网络搜索等启用项会明确报错。

角色卡提示词、玩家人设和作者注释不会自动加入任务。需要这些内容时，请在任务预设、提示词的宏或模板中显式读取。任务不会自动执行酒馆全局或角色正则。

## 创建任务

在“规则编辑”页新建任务，明确选择已绑定预设的 API 配置，填写任务提示词。任务不再单独选择预设，卡片和编辑器会显示 API、模型、预设组合，可直接跳转修改 API 绑定。列表支持搜索，并显示任务的规则组引用；编辑器按基础、世界书、正则和结果分区。新建任务默认启用，历史消息条数为 2，执行顺序为 0，楼层间隔为 1，失败重试为 0。复制任务会生成独立配置；删除任务也会移除所有规则组对它的引用。

“启用任务”对自动、手工和事件入口都生效。执行顺序数值越小越先执行；同一顺序的任务可并发，不同顺序分组依次执行。负顺序用于发送消息阶段，并等待该阶段结束后继续正文；非负顺序用于正文接收后的常规任务及界面的手工运行。

历史条数限制本次明确提供给任务的历史范围；0 不提供聊天历史。自动触发楼层间隔依据此任务在当前聊天中的最近成功楼层计算。显式事件绕过该间隔，但成功仍推进成功历史。失败重试用于未提交的生成和提取步骤，写入冲突不会通过再次调用模型自动消失。

### 世界书候选池与扫描

在任务的世界书分区直接读取酒馆书单，搜索选择世界书，再搜索、勾选条目；界面保存对应 UID，无需手填。也可添加按条目名称匹配的正则，并从正则库复用。条目勾选与名称正则取并集并去重；两者都为空不会选择该书的全部条目。要按名称选择全部条目，可明确填写匹配所有名称的正则 `.*`。读取失败时查看错误并重试，已保存的选择不会因此清空。

候选条目只在任务副本中强制启用，仍要经过关键词、概率、分组、预算、递归、位置与时序等扫描规则；加入候选池不保证最终发送。原世界书条目的启用状态不被修改。正文继续使用酒馆自己的世界书配置，本插件没有“正文配置”或正文专用过滤入口。

“世界书扫描参数”保存此任务自己的扫描设置，不随主聊天后续修改变化。默认扫描深度 2、预算为上下文的 25%、包含消息名称，不启用递归。扫描深度 0 表示没有普通历史扫描文本，不表示扫描所有历史；常驻和 sticky 等仍按各自规则判断。其余参数的精确含义及默认值见[目标契约](../AI2AI/API/分步任务目标契约.md)的“扫描配置和时序”。sticky、cooldown 和 delay 按任务与聊天隔离，只有任务成功才推进状态。

### 正则与输出

“正则测试”提供可搜索的正则库、编辑与测试区，支持新增、更新、删除、JSON 导入导出，以及匹配、提取和替换预览。表达式和 flags 分开保存；非法表达式会明确提示。正则预设可应用到任务显式正则、世界书名称匹配、输出提取和目标替换配置；预设复用是复制当前值，修改库不会悄悄修改已配置任务。

“导入旧版正则库”用于恢复仍保存在脚本变量 `saved_regex_configs` 中的库；旧 `{id,name,regex}` 文件也可导入。保存新任务配置不再删除旧库源数据。库与任务编辑一样先保存在草稿中，完成后点击“保存配置”。已有 schemaVersion 1 配置没有正则库字段时按空库加载，不要求重新配置。

从任务字段进入测试器后，可将调试结果“应用回当前字段”，再保存配置。若在测试器中先保存、撤销或导入配置，旧字段关联会明确结束，测试文本保留；需要应用时重新从目标字段打开测试器。

在“显式任务正则”中选择历史、世界书、请求消息或模型响应阶段，填写匹配表达式、flags 和替换文本。规则按列表顺序执行，可单独停用、上移或下移；保存时检查正则是否合法。

输出方式有两种：

- **仅返回结果**：生成文本放入任务结果，不写正文或世界书。
- **写入目标**：添加一个或多个写入，选择当前正文消息或世界书条目，再设置追加或正则替换。未设置提取规则时使用完整响应；各提取规则分别匹配完整响应，命中结果按列表顺序换行拼接，均未匹配会失败。替换条件已不匹配时报告冲突，不自动改为追加。

世界书写入目标可直接选择酒馆中的书和已有条目，界面绑定对应 UID 与名称；新目标填写明确的新建名称。未指定 UID 时，唯一同名条目可绑定；同名条目不唯一会要求明确选择。目标条目不存在时自动创建并启用，已有条目的其他属性不因此改变。已指定 UID 后条目被删除、又出现同名其他条目时会报告身份冲突，避免写错对象。

写入型任务只有全部约定写入及所需 MVU 更新完成后才算成功。模型已经返回文本而写入失败时，结果仍是失败。

## 规则组与自动限制

在“规则组配置”新建组并勾选任务，再在“规则组选择”将其设为活动规则组。任务池中的任务只有被活动组引用后，才进入该组的执行范围；不选择活动组时，不执行其任务。规则组只组织任务，不配置正文世界书。

“自动常规任务的最少正文字数”默认 300，设置 0 可关闭限制。实际按 JavaScript 字符串长度检查；仅在自动接收正文入口检查，不限制事件、手工运行或发送前任务。第 0 楼保护也只用于自动常规入口。任务禁用、长度不足或楼层间隔未达到时，会显示跳过原因。

## 运行、取消和查看结果

在“运行结果”点击“运行当前楼层任务”手工运行当前最后一楼的非负顺序任务。运行列表显示所属事件或常规链、绑定楼层及运行标识，可点击“取消此运行”。切换聊天会取消旧聊天的在途运行，并禁止其继续写入新聊天。

同一聊天只能有一个在途常规链；同一脚本、同一聊天、同一事件名也只能有一个在途事件运行。重复触发立即返回 `busy`，不排队。不同事件以及事件与常规链可以并发。`busy` 中的 `requestId` 对应本次请求，`activeRunId` 指出占用运行，可用来定位或取消。

展开结果可查看每项任务的成功、失败、取消、跳过、尝试次数、生成文本、写入状态、错误与警告。“清空结果显示”仅清除界面的结果列表，不撤销写入，也不取消任务。

常规链某项最终失败或被取消时，停止本链后续任务并尝试撤销本链已经提交的修改。事件按任务独立结算：某项失败不会撤销其他成功任务，取消也不会把已成功的事件写入一并抹掉。回滚本身可能失败，应查看回滚错误和残留警告；尤其要避免事件与常规链修改同一文本范围或 MVU 路径。

### 回滚后重新计算的会话限制

“回滚后重新计算”先撤销当前最后一楼对应的上一条可用常规链日志，再启动新运行；事件成功结果不属于这条常规链日志。插件只保留当前脚本会话内可用的最近常规链提交日志，日志不是跨重载备份，也不是任意楼层的历史恢复工具。

重载脚本或页面后，即使聊天中的任务成功历史仍在，旧运行的提交日志也可能已经丢失。专用重算若发现当前楼层已有成功历史而没有可用日志，会明确失败并提示没有可用回滚日志，不声称已恢复原数据，也不直接再次生成。目标被外部编辑、切页、删除或重叠修改导致无法安全回滚时，也应先检查错误和现有内容。不要把普通手工运行当作恢复旧输出的替代操作。

## 前端或脚本触发事件

先给活动组内的目标任务设置“附加事件名”，例如 `my_summary`。这是额外的显式触发入口；填写事件名不会让任务退出按执行顺序组织的常规链。留空表示没有附加事件入口。触发名不能以 `:result` 结尾，也不能使用内部的取消、重算或结果频道名。

在具有酒馆助手事件 API 的前端或脚本中，先监听结果再发送事件。事件只接收一个可选的字符串请求 ID，不接收任意参数对象，也不会把事件参数自动写入提示词；其他输入通过既有变量、宏或模板显式读取。

```js
const requestId = crypto.randomUUID();
const listener = eventOn('my_summary:result', result => {
  if (result.requestId !== requestId) return;
  console.log(result.status, result.tasks);
  if (result.status === 'busy') {
    console.log('占用运行：', result.activeRunId);
  }
});

try {
  await eventEmit('my_summary', requestId);
} finally {
  listener.stop();
}
```

事件结果频道是“事件名 + `:result`”；常规链结果频道统一为 `kat_task_chain:result`。旧事件名和旧 `KatAsyncAnalyzeAPI` 没有兼容别名。需要直接获得 Promise 结果或指定楼层时，使用新 `KatTaskAPI.run({ messageId, eventName, requestId })`；取消指定运行可使用 `KatTaskAPI.cancel(runId)`，事件总线对应 `kat_task_run:cancel`。`kat_task_chain:rerun` 对应界面的专用重算，具有相同的会话日志限制。API 初始化、完整结果结构和错误约定见[目标契约](../AI2AI/API/分步任务目标契约.md#运行取消和结果)。

## 尚待真实宿主验证

目前仍需要在实际部署环境记录酒馆、酒馆助手、提示词模板扩展及 MVU 版本，并验证：

- 界面交互、原生预设上传下载及导回酒馆后的语义往返。
- 原版同源后端对连接凭据、响应错误和取消的处理，以及任务与主聊天请求实际重叠时的隔离。
- 原生世界书完整扫描边界、EJS 各阶段、任务预设读取及池外显式世界书读取。
- 正文、世界书和 MVU 实际持久化、聊天切换、重叠写入与回滚失败处理。

本地 mock、静态检查或构建通过不能代替这些宿主验收。遇到不支持的宿主接口或预设行为时，应查看明确错误并核对支持记录，不依赖旧全局切换机制继续运行。
