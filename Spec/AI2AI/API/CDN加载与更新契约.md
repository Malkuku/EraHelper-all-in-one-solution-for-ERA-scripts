# CDN 加载与更新契约

## 安装与来源

用户于2026-10-18确认：GitHub仓库特定目录保存按版本命名的核心代码，长期加载器通过jsDelivr加载选定版本，并提供公告刷新入口。

仓库固定为 `Malkuku/EraHelper-all-in-one-solution-for-ERA-scripts`，公告分支沿用默认分支 `master-erahelper`，目录为 `releases/mvu/`。核心入口仍为现有完整单文件ES模块，依赖酒馆及现有远程运行库。加载器在原脚本iframe执行核心，不创建另一个酒馆脚本或改变script ID。

## 公告格式

`releases/mvu/latest.json`：

```json
{
  "schemaVersion": 1,
  "latest": "2.0.0",
  "versions": [{
    "version": "2.0.0",
    "date": "2026-10-18",
    "changes": ["更新说明"],
    "artifactCommit": "完整40位小写提交号",
    "sha256": "index.js的64位小写SHA256"
  }]
}
```

版本号为无v、无前导零的三段正式版本。日期有效，说明非空；版本唯一，latest必须存在于versions。公告只描述正式产物，客户端不得从任意URL执行代码。核心地址由固定仓库、artifactCommit、`releases/mvu/{version}/index.js`构造。artifactCommit是产物提交，不是候选元数据sourceSha。

公告经默认分支jsDelivr地址读取。刷新入口仅针对该公告：打开官方清缓存页面，提供公告地址供玩家填写并完成验证码，再由玩家重新检查实际公告。2026-10-18核对官方页面源码，当前清缓存请求依赖reCAPTCHA，加载器不伪造或绕过验证码，也不将打开网页称为刷新成功。来源：[官方页面源码](https://github.com/jsdelivr/www.jsdelivr.com/blob/master/src/views/pages/tools/purge.html)。请求失败、旧公告、HTTP错误、格式错误和摘要不符必须可见，不能称为已更新。刷新不承诺全球缓存立即一致，不自动切换版本。

## 加载与切换

首次安装没有选定版本时，读取公告并选定latest；之后保存完整版本描述，启动直接加载该描述，不依赖最新公告成功，不随公告静默升级。存储限定原脚本ID，不触碰配置和密钥。

下载核心后先验证SHA256，再在当前iframe执行。每次iframe会话最多执行一次核心；执行失败可能已有部分副作用，重试必须重载iframe，不能原地再次执行。失败后仍可选择公告中的其他版本并保存、重载恢复，不在当前会话执行另一个核心；已有忙碌守卫继续生效。下载失败和摘要错误不执行核心。加载器管理入口在核心缺失/失败时仍可访问。

用户显式选择公告中版本、查看说明并确认后应用：预先下载并验证，确认可切换，再保存描述并重载当前iframe。核心有运行中任务时阻止切换；重载确认明确提醒保存全部草稿，运行日志与回滚Journal不跨会话恢复。再次检查忙碌状态应位于异步下载和确认之后，避免在等待期间新任务启动仍重载。

加载器独立提供版本管理入口，关于页链接到同一入口；完整脚本直接安装时显示当前安装方式，不能冒充已有加载器。

## 本地发布准备

延续 `release:prepare` 候选工具，不能把candidate直接当公告。

新增分两步的本地发布工具：

1. stage：读取并校验干净来源的候选包及摘要，将版本文件复制到 `releases/mvu/{version}/`；目录已存在则拒绝覆盖。此时不写latest公告。
2. announce：维护者将版本文件提交并推送后，指定包含产物的完整提交号；工具核对Git提交内文件与来源、通过该提交的jsDelivr地址取回核心和版本元数据核对后，才生成/更新本地latest公告。保留历史版本，不允许同版本改指其他提交或内容。公告随后由维护者审阅并提交发布。

两步均不自动提交、推送、建标签或Release，不触发正式发布。现有候选工作流继续只读。实际GitHub/jsDelivr、浏览器跨源模块加载与酒馆环境须单独验收；本地测试不代表正式版本已发布。
