# 分步分析契约

## 配置与持久化

配置保存在当前脚本变量中，由 `AsyncAnalyzeStore` 读写：`async_analyze_setting` 为规则组，`task_config_settings` 为独立任务池，`api_config_settings` 为模型配置，`active_rule_name` 为活动组，另有 `saved_regex_configs`、`saved_analyze_backup`。规则组通过 `task_refs` 引用任务名称。读取时会把旧 `staged_setting` 展开并迁入任务池；具体字段以 `src/MVU助手/AsyncAnalyze/types/AsyncAnalyzeSetting.d.ts` 为准。

`KatAsyncAnalyzeAPI` 暴露获取/设置 API 配置、读取/保存/清空模型设置的方法，由 store 同时挂到 `window` 和 `initializeGlobal`。

## 触发和执行

- `MESSAGE_SENT` 执行 `order < 0` 的已启用任务并等待完成；`MESSAGE_RECEIVED` 启动 `order >= 0` 的已启用任务。`kat_resend_mvu_update` 请求重算当前楼层。
- 活动规则组引用的任务可按 `event_name` 注册自定义事件监听。事件触发路径按事件名筛选；当前实现没有再检查任务 `enable`，改动时需单独评估兼容影响。
- 任务按 `order` 升序分组；同组任务共同收集结果，模型生成使用全局锁。`trigger_index` 与 `trigger_history` 控制楼层间隔，失败最多按 `reroll_count` 重试。
- 普通分步流程结束时发送 `kat_handle_mvu_finished`。该事件名由 `src/Constants/KatEvent.ts` 定义。

## 结果与恢复

任务结果可按 `merge_setting` 的正则提取后写入当前消息或指定世界书条目。旧 `<VariableInsert/Edit/Delete>` 标签会尝试转换为 `<UpdateVariable><JSONPatch>`。修改消息后由 `MvuUtil` 触发 MVU 解析和写入。

执行前备份当前消息、相关世界书条目及任务触发历史到 `saved_analyze_backup`。发生流程级错误时尝试回滚；回滚只针对备份楼层与当前楼层相同的情况。是否覆盖所有外部副作用尚未经过集成验证。
