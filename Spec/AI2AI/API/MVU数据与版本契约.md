# MVU 数据与版本契约

## 手动变量编辑与版本更新的共同目标边界

`utils/MvuEditTarget.ts` 是变量编辑和版本更新的唯一目标校验责任层，两入口不再调用 `MvuUtil.updateMvuDataByObj()` 重新定位最后楼层。它在会话中捕获聊天标识（聊天 ID、群组和角色身份）、明确楼层、原消息引用、swipe 和完整 `stat_data` 基线。界面展示绑定聊天、楼层与消息页，加载后出现新楼层也视为目标变化。

读取与提交都等待 `waitGlobalInitialized('Mvu')`，异步等待后复核身份。保存前同时比较当前 `stat_data` 与加载基线；聊天、最后楼层、消息对象、swipe 或变量发生变化时停止提交并保留草稿/预览，要求导出备份并重新加载。手动提交与任务提交/回滚共享中立 `utils/TargetLocks.ts` 的消息目标键；锁内重新校验基线、调用 setter 并核对写后结果，通知在锁外发出，避免通知监听器嵌套提交死锁。锁只串行化本插件的提交，不隔离真实宿主的其他写入，后者仍依赖乐观基线与写后检查。提交使用绑定的明确 `message_id`，保留 MVU 数据中的其他字段，只替换 `stat_data`；成功后发出 `mag_variable_update_ended`，新旧数据为独立快照。输入必须是 JSON 对象。

宿主 `replaceMvuData` 是异步接口，不提供跨聊天身份条件式提交。调用前检查与调用之间不插入异步等待；setter 返回及通知返回后还会再次核对身份与提交结果。setter 拒绝、保存期间身份变化、保存后数据被外部改动或通知失败时，界面明确报告“完成未确认/可能已有写入”，保留草稿/预览，不宣称保存成功，也不向新聊天执行补偿或自动覆盖重试。真实宿主内部提交时机仍需集成验收，不能把这些客户端检查宣传为宿主事务保证。

`EraEditStore.loadTarget()` 返回目标与基线，`saveEraEdit(object, target)` 必须传入加载时的目标并返回新的已保存基线。`getStatData()` 是读取便利入口，不为后续无目标保存授权。变量编辑树形和原始 JSON 共用当前有效草稿；保存与 JSON 导出均读取当前编辑模式的值，原始输入非法时阻止这两项操作并允许导出未解析文本。完整导入替换草稿、差分导入合并当前有效草稿，均需之后保存。重新加载成功才替换草稿；有修改时先明确确认放弃，加载失败保留已有数据。顶层路由缓存与隐藏窗口保留当前脚本会话内的草稿，不是跨页面重载备份。

## 独立任务边界

独立任务仍由 `TaskCommit` 绑定准入时的消息与 swipe，按任务契约进行最新目标读改写与补偿。手动编辑不建立任务 Journal。精确路径、数组与任务日志边界由 [分步任务契约](./分步任务目标契约.md) 统一规定。无关滑动消息等原有 `MvuUtil` 调用语义未因本次 UI 重构改变。

## 版本规则与检查

版本设置保存在当前脚本变量的 `era_data_rule.version_control`，字段为 `enable` 和 `lore_name`。`era_data_rule` 是保留的持久化键名，不表示已移除的 EraDataRule 引擎仍在运行。设置独立自动保存，读取和保存失败在界面可观察并可按原操作重试。当前版本读取自 `stat_data.system.当前版本`，缺失或 null 按 0，不能转换为有限数值时明确失败；界面不再用 `toFixed(1)` 舍入版本，1.04 与 1.05 可区分。

指定主世界书的唯一同名条目中的更新块采用 `<del|v="版本号">JSON</del>` 或 `<edit|v="版本号">JSON</edit>`。按数值版本升序解析，只应用高于当前版本的块。`del` 递归删除字段，`edit` 递归合并对象并覆盖标量或数组；两者支持 `$all` 应用到子对象。预览生成最终完整 `stat_data`，并设置 `system.当前版本` 为目标版本。

世界书读取失败、条目不存在/重名/为空、没有有效更新块、更新块格式损坏、无效版本号或 JSON 损坏/非对象都会明确失败，不能静默跳过损坏块后宣称最新。成功检查且没有高于当前版本的块，才显示无需更新。

## 更新预览与执行

检查前绑定目标，读取规则后再次核对目标与基线，再生成预览。预览保存来源世界书/条目与原规则内容、绑定目标、原版本/目标版本、原始变量、最终变量以及逐路径的新增/删除/修改。界面一次呈现原值与新值，支持按路径搜索、完整结果展开及导出原始变量和更新预览，不再要求用四次点击逐步揭示内容。

执行前重读相同来源并比较规则原文，然后再次核对目标与变量基线，最后通过共享目标保存函数提交；来源变更停止旧预览执行。只有所有提交与完成确认成功后才清除预览并更新已保存版本。提交失败保留预览和差异，展示具体原因，不跳回初始页、不提前提高当前版本；选择不同来源或关闭功能后旧预览保留供比较，但必须重新检查后才可执行。

确定性验证的唯一主要入口为 `tests/mvu-editing.cjs`，覆盖目标漂移、异步边界、外部基线变化、规则错误、精确版本及失败预览保留；浏览器与真实宿主门禁见测试方案与本轮独立验收记录。客户端模拟不能证明真实 MVU 持久化和宿主异步写入的事务性。
