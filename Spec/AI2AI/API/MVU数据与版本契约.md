# MVU 数据编辑契约

## 手动变量编辑的目标边界

`utils/MvuEditTarget.ts` 是手动变量编辑的唯一目标校验责任层，该入口不再调用 `MvuUtil.updateMvuDataByObj()` 重新定位最后楼层。它在会话中捕获聊天标识（聊天 ID、群组和角色身份）、明确楼层、原消息引用、swipe 和完整 `stat_data` 基线。界面展示绑定聊天、楼层与消息页，加载后出现新楼层也视为目标变化。

读取与提交都等待 `waitGlobalInitialized('Mvu')`，异步等待后复核身份。保存前同时比较当前 `stat_data` 与加载基线；聊天、最后楼层、消息对象、swipe 或变量发生变化时停止提交并保留草稿，要求导出备份并重新加载。手动提交与任务提交/回滚共享中立 `utils/TargetLocks.ts` 的消息目标键；锁内重新校验基线、调用 setter 并核对写后结果，通知在锁外发出，避免通知监听器嵌套提交死锁。锁只串行化本插件的提交，不隔离真实宿主的其他写入，后者仍依赖乐观基线与写后检查。提交使用绑定的明确 `message_id`，保留 MVU 数据中的其他字段，只替换 `stat_data`；成功后发出 `mag_variable_update_ended`，新旧数据为独立快照。输入必须是 JSON 对象。

宿主 `replaceMvuData` 是异步接口，不提供跨聊天身份条件式提交。调用前检查与调用之间不插入异步等待；setter 返回及通知返回后还会再次核对身份与提交结果。setter 拒绝、保存期间身份变化、保存后数据被外部改动或通知失败时，界面明确报告“完成未确认/可能已有写入”，保留草稿，不宣称保存成功，也不向新聊天执行补偿或自动覆盖重试。真实宿主内部提交时机仍需集成验收，不能把这些客户端检查宣传为宿主事务保证。

`EraEditStore.loadTarget()` 返回目标与基线，`saveEraEdit(object, target)` 必须传入加载时的目标并返回新的已保存基线。`getStatData()` 是读取便利入口，不为后续无目标保存授权。变量编辑树形和原始 JSON 共用当前有效草稿；保存与 JSON 导出均读取当前编辑模式的值，原始输入非法时阻止这两项操作并允许导出未解析文本。完整导入替换草稿、差分导入合并当前有效草稿，均需之后保存。重新加载成功才替换草稿；有修改时先明确确认放弃，加载失败保留已有数据。顶层路由缓存与隐藏窗口保留当前脚本会话内的草稿，不是跨页面重载备份。

## 独立任务边界

独立任务仍由 `TaskCommit` 绑定准入时的消息与 swipe，按任务契约进行最新目标读改写与补偿。手动编辑不建立任务 Journal。精确路径、数组与任务日志边界由 [分步任务契约](./分步任务目标契约.md) 统一规定。无关滑动消息等原有 `MvuUtil` 调用语义未因本次 UI 重构改变。

## 已移除的角色数据版本更新

角色卡数据迁移由角色卡负责。助手不再读取或保存 `era_data_rule.version_control`，不再解析世界书 `<edit|v="…">` / `<del|v="…">` 更新块，也不提供版本预览、执行和启动检查。已有设置、世界书、消息变量及 `system.当前版本` 不自动删除或改写。

助手自身的脚本升级属于另一项职责，尚未实现。
