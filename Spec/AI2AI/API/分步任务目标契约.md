# 分步任务契约

状态：2026-10-17 已完成新生产路径切换，G0 已冻结；确定性行为验证与宿主集成验收分开记录，不能据本契约宣称宿主已通过。入口导航见 [分步分析契约](./分步分析契约.md)，生成决策见 [任务生成隔离方案](../决策/2026-10-16-任务生成隔离方案.md)，进度与证据见 [迭代任务](../迭代任务/2026-10-16-独立生成与并发任务重构.md)。

## 配置与兼容边界

2026-10-16 用户明确允许不兼容旧版本的破坏性更新，以代码干净性为准。允许重新设计本模块的配置 schema、API、事件载荷与存储，不要求兼容旧 Profile、Sample/External 分支及旧配置结构，不要求自动迁移旧配置。新格式是唯一权威路径，不保留仅服务旧版的字段、别名、转换链和 fallback。

不兼容不意味着静默接受无效配置：不支持的旧格式须明确提示重新配置。旧模块数据的清理范围仅限本模块负责的配置和状态，不得清空其他模块变量或用户正文、世界书内容。原生酒馆预设 JSON 的兼容性是本轮产品要求，与放弃旧插件配置兼容是两个独立边界。

## 触发与运行隔离

- 常规链保留按 order 分组、组间有序、同组任务并发的业务含义。MESSAGE_SENT 中负 order 任务仍需完成后再继续正文生成；这是显式业务顺序，不是主聊天与任务共享生成锁。
- 不同事件可以并发，事件与常规链可以并发；事件无需等待常规链最终提交，允许读取其中间状态。
- 同一事件名只允许一个在途执行，重复触发立即返回明确 busy 结果，不排队，不静默丢弃。
- 各运行有自己的任务身份、取消状态和结果。一个运行失败、取消或重试不能通过全局 runId 作废其他无关运行。
- 事件参数不新增一套隐式提示词注入机制；既有酒馆变量、宏与模板仍可传递前端内容。

事件与聊天作用域、常规链重复触发、enabled 和间隔规则以本次恢复的原版语义为准。附加事件名增加显式入口，不使任务退出常规链；enabled 只控制常规入口，关闭常规参与后仍可通过事件执行。

## 结果与输出

- 每个任务须有明确状态及失败原因，不能只返回整组 success。
- 提供纯结果返回模式：不写正文或世界书，将生成文本随任务结果交给调用方。
- 写入型任务只有在约定的正文、世界书及 MVU 更新完成后才算成功；模型返回文本不等于任务成功。
- 事件结果频道为 `${eventName}:result`，同名事件的 busy 也发出可关联的结果；确切字段见下文。
- 事件任务一组独立结算：一个任务失败不回滚其他任务已成功提交的结果。常规链仍整链失败回滚；回滚本身失败也须报告。

## 并发写入与恢复

- 提交正文消息或世界书条目时基于最新内容执行读改写，避免旧快照覆盖其他运行。替换条件不再匹配时报告冲突。
- 允许按写入目标短暂互斥；不得用同一锁串行整个生成及网络等待。
- 备份与回滚仅覆盖本次实际执行任务及其目标，运行之间不共用会被覆盖的单份备份。
- 开发者应配置事件和常规链写入不同目标；检测到重叠时警告后继续，不据此排队或拒绝事件。结果应提示常规链回滚可能影响重叠的事件写入。
- 不同目标时，常规链回滚不得抹掉事件已提交的数据。同一正文消息的独立片段与 MVU 独立 JSON 路径按下文所有权规则处理，不能回写整条旧消息伪装为隔离。
- 不承诺目标重叠时同时满足完整回滚和事件写入原样保留。

## 任务候选池与正文边界

新版本没有插件提供的“正文配置”或正文专用世界书过滤能力。旧规则组的正文 world_book 字段、对应 UI、过滤钩子、共享黑白名单及恢复机制全部退出，不拆成新的正文过滤模块继续保留。

世界书候选池只属于任务，任务在自身上下文中摘取、强制启用并扫描条目。正文由酒馆自身的配置和生成流程处理，插件不为任务需要改变正文的条目范围。规则组仍可组织和引用任务，不再承载正文世界书配置。

## 密钥

连接密钥存于浏览器本地持久化，普通配置只保存引用；普通配置、角色卡和预设导出不携带插件连接密钥。不保留脚本变量内明文密钥的生产读写路径。允许不迁移旧密钥，用户重新填写；遗留明文清理属于旧职责取缔，不据此建立旧配置兼容体系。不以防范同源脚本读取为本轮目标。

以下技术接口已由协调 Agent 审阅并用于本轮实现；实际宿主验证仍见独立验收记录。用户已确认玩家人设和作者注释不自动加入，只通过宏或模板显式读取。

### 已确认的运行规则（2026-10-16）

- `enabled` 只控制是否参加常规链；事件匹配 eventName，不检查 enabled。无事件名且关闭常规参与的任务没有普通执行入口。
- 规则组和任务编辑明确区分“参加常规链”与“事件触发”；关闭常规参与的事件任务依然可执行。字段 hover 说明同时支持键盘焦点与点击。
- 常规链和整组事件入口均遵守触发间隔；显式指定 taskId 的单任务测试跳过间隔，普通任务测试仍检查 enabled。
- 同一聊天只允许一个在途常规链，重复触发返回 busy，不排队。
- 切换聊天取消原聊天在途运行，并禁止后续写入；不让旧运行写入新聊天。
- 同名事件忙碌键为脚本身份、聊天身份及事件名的组合；不同聊天的同名事件不共享 busy 状态。
- 世界书时序状态以 task + chat 隔离；本次任务成功结算后才推进。失败、取消不推进。
- 任务可勾选 `useTavernRegex`，对正文历史输入复用酒馆当前启用的全局、预设和局部正则；缺省 false，未勾选时仅执行显式任务正则与模板阶段处理。正则来自酒馆当前预设，不是任务 API 绑定的预设副本。

- 自动 `MESSAGE_RECEIVED` 的正文长度限制可配置，字段 `automatic.minReceivedChars` 默认 `300`，按 JavaScript 字符串 length 检查；值为 `0` 关闭该限制。只在该入口检查，事件、手工及 `MESSAGE_SENT` 不受该阈值限制。0 楼保护只用于自动常规入口。
- 世界书目标不存在时自动创建并启用；已存在条目的其他属性不因写入内容而自动改变。

以上是已确认目标；G0 技术契约已审阅冻结，实施与验收状态见迭代任务。

### 权威数据与持久化

- 脚本变量仅新增一个 `async_task_config` 根，`schemaVersion: 2`。根含 `activeGroupId`、`automatic: { minReceivedChars: 300 }`、`groups`、`tasks`、`connections`、`presets`、`regexPresets`。所有实体用稳定 ID 引用，名称只用于显示、导入覆盖提示与编辑，不再兼任运行身份。2026-10-17 用户确认预设绑定 API；独立任务版本 1 在加载、导入和 setConfig 边界统一经 `parseTaskSettings` 升级：按既有 connectionId/presetId 组合建立 API 配置，同连接不同预设拆分并保留原 secretRef；未引用的连接保持未绑定，不猜测预设。转换不改原任务运行组合，保存后持久化版本 2；此边界不恢复旧 Profile 配置。
- `regexPresets` 为 `{ id, name, pattern, flags, replacement }[]`，缺省为空数组，replacement 缺省为空字符串；既有版本 1 配置仍可加载。正则库仅提供编辑时复制复用，不作为运行时第二套规则来源。旧 `saved_regex_configs` 是用户正则库数据，不随旧运行配置清理删除；界面提供显式导入，支持旧 `{id,name,regex}` 库格式，不自动恢复旧任务或全局生成机制。
- 正则库、测试器及任务正则字段统一使用单个表达式输入框，不拆出 flags 输入。直接输入表达式按无标记处理；完整 `/表达式/gi` 写法由共享 `parseRegexInput` 解析，已有标记通过完整表达式回显并保留。内部 pattern/flags 存储和运行匹配语义保持一致。
- `Group` 为 `{ id, name, comment, taskIds }`，没有正文世界书字段。
- `Connection` 为 `{ id, name, comment, baseUrl, model, secretRef, presetId }`。API 配置是预设绑定的唯一权威来源，任务选择 API 即确定模型及预设；修改绑定在保存后影响全部引用任务。presetId 可为 null 表示待绑定；未绑定或绑定丢失仍允许任务引用并保存，相关任务运行时才报告缺失。协议固定 OpenAI 兼容 Chat Completions；没有独立采样字段、Profile 或跟随当前配置选项。
- `PresetRecord` 为 `{ id, name, raw }`，`raw` 是原生酒馆 JSON 的完整副本。轻量编辑视图从 `raw` 派生；保存时直接修改 `raw` 对应字段，不持久化第二份规范化预设。未知字段与未启用提示词原样保留。导出只输出 `raw`，插件记录的 ID 和名称不混入原生协议。
- `Task` 含 `{ id, name, comment, enabled, eventName, order, historyDepth, useTavernRegex, triggerInterval, retryCount, prompt, connectionId, candidateBooks, scan, regexRules, output }`，不再持有 presetId。沿用现行界面字段的默认含义：order 为 0、historyDepth 为 2、useTavernRegex 为 false、triggerInterval 为 1、retryCount 为 0；事件同样检查 triggerInterval。enabled 与 eventName 在保存时显式提供，connectionId 可为空字符串表示未选择 API；保存不要求连接或预设已完整，相关任务运行时才验证。
- `candidateBooks` 显式登记书名、条目 UID 选择与名称正则摘取。运行开始时解析并复制实际条目，按 `bookName + uid` 去重；只在副本内强制启用。不沿用全局黑名单或复用正文过滤状态。
- 世界书条目选择列表展示名称、勾选状态与名称正则命中提示，不常驻展示 UID 和宿主启停状态；条目仍按 UID 选择/持久化，UID 搜索及缺失条目诊断保留。
- `scan` 保存本任务扫描配置；运行时不持续跟随宿主设置。精确字段、默认值和来源见下方“扫描配置和时序”，不继承主聊天运行状态。
- `regexRules` 是任务的显式有序数组：`{ id, stage: 'history' | 'worldinfo' | 'prompt' | 'response', pattern, flags, replacement, enabled }`。pattern/flags 保存为独立字符串字段，允许未完成表达式保存，在相关任务运行前编译校验，replacement 使用 JavaScript replace 的捕获语义；输出提取正则另存于 WriteSpec，避免提示词转换与输出匹配混用。不复制或持久化宿主正则列表。
- `useTavernRegex` 为正文历史输入开关，配置版本仍为 2，旧配置缺省关闭。启用时在 `GenerationHost.createGenerationContext` 对每条原始历史调用 `formatAsTavernRegexedString`，来源按 is_user 区分 user_input/ai_output，目标为 prompt，depth 按当前完整聊天中该条消息距末条的楼层距离传入；实际规则顺序、启停、局部/预设授权及深度筛选由宿主引擎决定。之后再执行显式 history 正则及姓名/引号格式化；请求历史和扫描历史共用处理结果。仅格式显示的正则不用于输入，开关不处理任务提示词、世界书或模型响应，不改写聊天原文；历史深度 0 不调用宿主接口。接口失败向上报告，不静默改用未过滤原文。
- `output` 为判别联合：`{ mode: 'return' }`、`{ mode: 'event_result' }` 或 `{ mode: 'write', writes: WriteSpec[] }`。event_result 为明确的事件结果广播模式，仅实际事件运行允许，完整响应在一次终态 `${eventName}:result` 的 tasks[].text 中交付，不持久化结果，不写正文/世界书/MVU；请关闭此任务的常规链参与，误入常规入口在 prepare 明确失败且不请求模型。return 同样将文本放在结果中，事件触发时沿统一频道交付，不建立第二套频道。写入描述含稳定 `id`、目标、提取正则和追加/替换操作；不存在“空 merge 自动追加正文”的隐藏输出方式。世界书目标为 `{ kind: 'worldbook', bookName, entryUid?: number, entryName }`；entryUid 绑定已有条目，entryName 是缺失时创建所需的明确名称。
- 密钥在宿主同源 localStorage 命名空间 `kat.async-tasks.secrets.v1:<scriptId>` 中保存，普通配置只存随机引用。运行快照只能在内存取出密钥，不进入日志、结果对象、JSON 导出或预设副本。
- 运行历史和时序状态保存于聊天变量 `kat_async_task_state:<scriptId>`，按 task ID 隔离并仅在成功结算后推进。Journal、最后可重算常规链、在途状态与未恢复诊断只在本次脚本会话内存，不复用旧全局备份，也不承诺跨重载恢复。
- 检测到旧模块配置而无新根时，返回明确的 `unsupported_config` 并显示重新配置入口，不读取旧配置执行任务。清理旧明文时只删除旧模块 API 配置中的密钥字段，不覆盖其他脚本变量。

### 编辑、删除与运行前验证

配置版本保持 2。持久化校验数据形状、稳定 ID 唯一性、组引用结构及 raw 的 JSON 对象形状；不以全局完备性阻止保存、重载、配置导入导出。名称、API 地址与模型可以为空，预设可以缺预算，任务可以未选择 API，世界书写入目标和表达式可以尚未填完。非法 JSON、错误实体结构和重复 ID 仍明确报错。

资源删除的共享权威为 `TaskConfiguration.removeTaskResource(settings, kind, id)`，纯函数返回新配置：删除 API 保留任务并将其 connectionId 清为 `''`；删除预设保留 API 并将 presetId 清为 null；删除任务只移除组内对应 taskIds；删除活动组将 activeGroupId 清为 null。不得阻拦引用中的资源删除，也不得级联删除使用方。保存成功后，`TaskStore.replaceSettings` 清理本模块未被任何连接 secretRef 引用的本地密钥，共享引用仍保留。密钥清理在配置成功落盘后独立执行；本地密钥损坏或清理写入失败不阻止配置保存、不将已保存配置报为失败，store.configurationWarning 明确显示配置已保存及清理未完成，后续清理成功时清除。真正运行时读取损坏密钥仍明确失败。

预设轻量编辑使用 `NativePresetEditorSchema` 和 `preparePresetEditor` 的提示词/顺序编辑形状，不依赖运行预算或顺序引用完备性；缺少编辑数组与全局顺序时仅补这些编辑容器。仍直接编辑 raw，不增加第二份持久化预设。真实数组形状错误需明确提示，不因预算缺失锁住提示词编辑。

`TaskConfiguration.validateTaskReadiness(settings, task)` 是运行前配置完备性的唯一责任点，TaskRuntime 和独立 GenerationHost 入口均消费它。它只验证将执行的任务及其 API/预设、启用的转换正则、候选书和输出目标；不检查闲置任务、未引用连接/预设或正则库。缺引用为 `missing_config`，地址/模型/表达式/目标未完成为 `invalid_config`，预设语义错误为 `invalid_preset`，均在 prepare 阶段明确失败且不发出模型或分词 HTTP。有效任务不因闲置坏资源失败；实际被选中的常规链任务仍遵守已有整链回滚规则。

非法或内部 eventName 可以保存在草稿配置中，但不注册为事件监听器；运行所选任务时报告无效配置。公共 API 显式事件入口仍拒绝非法请求，避免内部结果频道递归。

### 运行、取消和结果

每次入口同步分配 `requestId`，调用方可提供字符串 ID；内部始终生成唯一 `runId`。自定义事件接受可选字符串 requestId，或对象 `{ requestId?: string, messageId?: number, taskId?: string }`；缺省楼层为触发时最后楼层，不把参数自动变成提示词。非法参数返回 invalid_request 并发布对应终态。重复请求的 busy 结果带本次 `requestId` 与占用者 `activeRunId`。

`TaskRun` 持有 `{ runId, requestId, taskId, attempt, trigger, chatIdentity, messageIdentity, configSnapshot, presetSnapshot, candidateEntries, historySnapshot, scanStateSnapshot, messages, controller, result, journal }`。不使用单一全局 runId 作废其他运行。重试重用本次配置快照，重新生成本任务请求，不能重发已经提交的写入。

`MESSAGE_SENT` 的负 order 链与 `MESSAGE_RECEIVED` 的非负 order 链是两个独立 run，前者 await 自己终态后正文继续；不跨主聊天 HTTP 持有 busy、备份或待回滚日志。触发间隔恢复原版：基线缺省0；间隔1不限制同楼重复触发；间隔>1时，当前楼层减上次触发基线达到间隔才执行，事件也检查。当前楼层低于基线时本次跳过并重置基线，独立 triggerBaseline 不伪造成功历史。成功推进基线、成功历史和时序；失败、取消、整链回滚不推进成功历史。单任务显式测试绕过间隔。未达间隔返回 skipped/interval_not_reached 与本次/上次触发楼层。

整体状态聚合：准入拒绝是 busy；无运行任务（禁用/间隔/空清单）为 skipped 并列每项原因；事件全部成功为 succeeded，有成功与失败为 partial，无成功且失败为 failed；取消触发的运行最终为 cancelled，已经成功的事件任务仍保留 succeeded，结果显式表达这些保留写入。常规链全部成功为 succeeded，任一任务最终失败为 failed 并回滚，取消为 cancelled 并回滚；不能因为补偿成功就把运行改成 succeeded。rollback.status 独立表达补偿状态；常规链原来成功的任务按撤销结果改成 rolled_back/rollback_failed。

配置、活动组和任务清单在运行准入时复制；每个任务进入生成阶段时，绑定本次聊天/目标消息/页身份并读取历史和候选条目。跨组任务可读到前组已提交结果；同组任务各自取得阶段输入，不在网络返回后重新组装提示词。宿主宏与 EJS 主动读取当前聊天的已接受窗口风险继续单独说明。

`KatTaskAPI` 是新的唯一前端入口，不保留旧 `KatAsyncAnalyzeAPI` 别名。共享类型位于 `@types/iframe/exported.kat-task.d.ts`，指向 `TaskSchema.KatTaskAPI`；访问前等待 `waitGlobalInitialized('KatTaskAPI')`。

| `getConfig(): TaskSettings` | 返回配置副本，不暴露本地密钥 |

专用“回滚后重新计算”入口为按钮或 `kat_task_chain:rerun`。它在回滚前就占用本聊天常规 busy；该楼存在成功历史但重载后没有可用 Journal 时明确失败（rollback_unavailable），不恢复旧数据，也不发新模型请求。普通手动 run 仍遵守间隔规则。

事件结果频道为 `${eventName}:result`；常规链统一 `kat_task_chain:result`，旧完成事件同步替换其消费入口。每次触发恰好发一个终态结果，API Promise 返回同一个结构：

运行反馈由 `TaskRuntime` 统一通过宿主 toastr 展示，不依赖助手窗口或运行结果页是否打开。存在待执行任务时提示开始及任务名称；终态按整次运行提示成功、部分成功、失败、取消、忙碌或未执行，附楼层、事件名（如有）、结果数量、失败/跳过原因及回滚影响。常规链完成回滚前不报成功；回滚残留以错误提示，带警告的成功以 warning 提示。自动发送/接收检查的 skipped/busy 不弹提示，显式手动/事件请求仍说明未启动原因。用户文本按纯文本转义；通知异常只记录日志，不改变任务结果、终态事件和锁释放。

任务配置的空 eventName 表示不注册附加事件，纯空白或首尾空白的事件名无效。内部 `kat_task_chain:result`、`kat_task_chain:rerun`、`kat_task_run:cancel` 以及以 `:result` 结尾的触发名均拒绝注册。API run 中显式事件名、消息非负整数和可选字符串关联 ID 同样校验。不以事件总线监听顺序避免递归。

取消只 abort 所属运行请求；等待同组已启动任务全部结算后再回滚，避免晚返回写入。组结果按配置引用次序表达，与网络完成次序无关。事件运行中成功任务即时独立结算；失败任务的局部提交只撤销自己的日志。常规链失败后停止后续组、取消本链尚未完成请求并撤销本链日志。尚未进入的任务以 skipped 和具体原因进入结果。API 返回、事件载荷和 UI 缓存分别复制终态快照；后续重算不会修改旧结果。

HTTP 非 2xx、后端 error、响应缺失文本、JSON 解析失败、取消分别映射明确错误码。不能用通用文案抹去后端实际原因：HTTP错误同样读取正文；JSON error.message、字符串error与根message可提供原因，非JSON文本/HTML保留为纯文本诊断。TaskError可选details包含connectionName、model、endpoint、elapsedMs、httpStatus?、statusText?、backendCode?、backendType?、response?。response脱敏后最多12000字符并明确标记截断，endpoint不带URL凭据/查询串。运行页直接显示请求上下文并默认展开失败响应；复制诊断与事件结果保留同一details。

控制台沿既有eraLogger输出运行准入、任务开始、跳过及原因、每次生成/重试、世界书扫描数量、连接/模型/预设与请求耗时、提交、取消、失败、回滚和最终结算；每条携带runId与任务身份，运行层另有requestId。调试级别保留实际请求内容和模型原始输出，Authorization头不打印，已知任务密钥和常见凭据字段脱敏；日志异常不改变业务结果。重试只发生在未提交的生成/提取步骤；提交冲突不通过重复调用模型掩盖。

### 目标身份、提交日志与回滚

- 消息身份绑定聊天文件、角色/群组身份、消息索引及 swipe ID；运行持有宿主 `SillyTavern.getContext().chat[messageId]` 的原始对象引用，不能用 getChatMessages 返回副本的引用作为身份。提交时校验 chatId/角色或群组/avatar、原始引用仍在同一索引、swipe_id 相同，并校验最新数据；对象被替换或移位返回 target_changed，不能靠正文相等猜测身份。世界书绑定书名与条目 UID，禁止按名称找到第一个条目就写入。每次有副作用的 await 前后校验目标身份，消息删除、移位或 swipe 切换不能写到新的“最后一楼”。
- 世界书无 entryUid 时，在书锁内按明确名称查询：唯一同名条目可绑定 UID，多个同名条目报告 ambiguous_target 并要求用户选 UID；无同名条目才创建 enabled 条目。已指定 UID 却消失时，只有原创建名称也不存在才自动创建；存在同名其他 UID 报告身份冲突，避免写进被删除后重建的另一对象。并发创建在同一书锁内再次查询，后一运行复用前一运行刚创建的唯一 UID，不重复创建。新建条目使用宿主默认字段并显式设置 name/content/enabled，不自行增加策略关键字。
- 锁只覆盖目标最新读取、条件校验、持久化与必要的 MVU 写入；不覆盖扫描、模板、模型网络等待。消息文本与 MVU 属于同一个消息事务资源；世界书 API 读改写以书为互斥粒度，条目 UID 仍是所有权边界，防止全书保存互相覆盖。
- 多目标任务按资源键稳定排序取得锁，避免相反写入顺序死锁。进入锁后重新读取最新内容并计算写入，不发送准备阶段复制的整条消息/整本世界书。
- 替换操作记录命中的原文片段、边界及替换文本；提交时重新匹配最新内容。目标条件已失效或目标身份改变返回 conflict；不能降级为追加、创建或全量覆盖。
- 每笔实际提交登记 `{ runId, taskId, writeId, target, beforeFragment, afterFragment, location, dependencies }`。同一消息不同范围、同一书不同 UID、MVU 不同 JSON 路径可以成为独立修改；不得仅以 messageId 相同就把整份消息视为回滚单位。
- 文本回滚按本次实际提交序列逆序撤销片段，不按模型完成或状态保存 ack 次序。插件已知并发修改变换日志位置；最新内容必须与本模块可信目标版本一致且该位置仍是本次 after 片段。遇到未跟踪外部修改时保守报告 rollback conflict，不用全文唯一字串搜索证明归属，更不写回整条旧消息。
- MVU 使用绑定消息的最新数据纯解析本次将提交的文本，await parseMessage 后才持久化正文/世界书，再 await replaceMvuData。解析前后差异按 JSON 路径记录；等长密集数组的既有索引递归记录，长度或容器形状变化按父数组整体记录。索引日志同时保护祖先数组长度；同路径、祖孙路径和父数组结构写入是重叠，独立索引不是。提交时即给重叠警告，回滚还需校验 after 值和数组结构归属。任务不调用 MvuUtil 的 last-message helper；无关模块能力保留。
- 宿主没有跨正文/MVU/世界书的原子事务，本模块采用提交日志补偿。先完成可纯计算的提取、条件与 MVU 解析，再持久化；中途失败立即补偿已完成写入。补偿失败必须保留日志并在结果暴露，不宣称成功或原子回滚。
- 已知事件与常规链的目标区间/路径相交时记录 overlap 警告并继续；粗粒度目标相同而实际范围互不相交时可继续独立回滚。重叠修改无法安全逆转时报告残留项，不能为了“完整回滚”删除无关运行的数据。
- 创建条目日志登记新 UID、完整初始内容与 createdByRun。只有条目仍只包含本运行所创建的内容/属性且没有后续运行写入，回滚才删除该 UID；其他运行已经写入时保留条目，只逆向撤销本运行仍可定位的片段，并给 created_target_retained 警告。外部编辑破坏归属时返回 rollback conflict，不能整条删除。
- 宿主 setter 的 Promise reject 不能证明未写入。文本和 MVU 在等待 ack 前登记尝试，按实际 before/after 检查零写入或补偿；条目创建未返回 UID 时登记 create_pending，不能证明新 UID 归属时保留并明确报告残留，不能猜测删除。状态写入同样按 owner/sequence 核对并补偿；保存后聊天身份失效不越聊天补偿，携完整 StateUndo 留作诊断。
- 补偿失败的剩余 Journal/StateUndo 由 runtime 保留到本会话结束，统一 RunResult 保持业务终态。只读诊断移除宿主原始消息引用，返回深拷贝；成功补偿不留下假失败记录，清空 UI 结果显示不删除诊断。

`WriteSpec` 精确结构如下；所有写入均为任务成功所需操作，不存在某条写入失败后继续报任务成功。

```ts
type RegexSpec = { pattern: string; flags: string };
type WriteSpec = {
  id: string;
  target:
    | { kind: 'message' }
    | { kind: 'worldbook'; bookName: string; entryUid?: number; entryName: string };
  extract: RegexSpec[];
  operation: { kind: 'append' } | { kind: 'replace'; regex: RegexSpec };
};
```

extract 为空使用完整生成文本；非空则按配置次序提取每个 regex 的整个匹配 match[0]，g 标志提取全部，否则只提取首次，结果以换行连接；这沿用现行 RegexUtils 的完整匹配语义，不自动改成 capture[1]。某个 regex 无匹配可贡献空列表，整个 write 的所有 regex 均无匹配则 extraction_failed；提取后的空白内容为 empty_result，不创建空条目或假报成功。正则语法在相关任务运行前校验，保存与导入保留未完成表达式，运行不得吞异常。替换正则带 g 时替换所有匹配，否则替换第一个，0 匹配为 conflict；每个实际匹配分别记日志。提取文本按字面量替换，采用 replacement callback 避免模型输出中的 `$&`/`$1` 被误解释。追加与非空目标之间补一个换行，空目标直接赋提取文本；同一 task 的 writes 按配置顺序执行。

**扫描配置和时序**

`Task.scan` 必填，编辑器创建任务时按原版 world-info.js 的声明默认值初始化：`depth: 2, minActivations: 0, minActivationDepthMax: 0, budgetPercent: 25, budgetCap: 0, includeNames: true, recursive: false, caseSensitive: false, matchWholeWords: false, useGroupScoring: false, maxRecursionSteps: 0`。这些是原版算法的参数映射，不读取主聊天后续修改。条目 `scanDepth/caseSensitive/matchWholeWords/useGroupScoring` 的 null 继续表示取本任务 scan 值。预算为 `round(budgetPercent * preset.openai_max_context / 100) || 1`，budgetCap 大于 0 才限制；递归、最少激活和分组逻辑直接移植原版，不增加插件自己的阈值。候选池已显式提供，不再需要宿主全局书/角色书合并来源的优先策略。

schema 数值范围：order 为有限整数（允许负数）；historyDepth/minReceivedChars/minActivations/minActivationDepthMax/budgetCap/maxRecursionSteps 为非负整数；scan.depth 为 0..1000（1000 来自原版 MAX_SCAN_DEPTH）；triggerInterval 为正整数；retryCount 为非负整数；budgetPercent 为 0..100 有限数；其余扫描开关为 boolean。depth 为 0 时原版 buffer.get 对 depth<=startDepth 返回空扫描文本，不代表扫描所有历史，constant/sticky 等仍按各自规则处理。Preset raw 中上下文与输出预算必须为正整数且输出小于上下文；flags 使用 JavaScript RegExp 合法标志并拒绝重复标志。candidateBooks 每项 `{ bookName, entryUids: number[], nameRegexes: RegexSpec[] }`，条目 UID 为非负整数；同书条目选择取 UID 与名称正则命中的并集，再按 bookName+uid 去重。

扫描历史是目标楼层及之前的最多 historyDepth 条已选择页消息，顺序按原版扫描器要求逆序，是否带消息名由 includeNames 控制；task.prompt 不作为额外 should_scan 注入，沿用现行任务注入 should_scan:false。条目主动指定的扫描深度也受本次明确提供的历史边界约束；不暗中读更早楼层。条目额外匹配角色/玩家/场景数据，只在原生相应 match 字段显式开启时由本次宿主上下文取值，不等于自动发送角色提示词。主聊天 extensionPrompts 和外部 WORLDINFO_FORCE_ACTIVATE 表不进入任务扫描。

时序时钟使用绑定目标的实际聊天楼层计数 `messageId + 1`，不使用 historyDepth 截取后的长度，不以任务触发次数伪装楼层。聊天变量根按 taskId 保存 `{ lastSuccessfulFloor?, ownerRunId?, sequence?, effects }`。effects 的键为 `sticky:<bookName.uid>` 或 `cooldown:<bookName.uid>`，值为 `{ value, settledFloor, sequence, ownerRunId }`；value 是原生时序记录 `{ hash, start, end, protected }` 或删除标记 null。delay 是 `floor < entry.delay` 的运行时条件，不另外维护倒计时。sticky/cooldown 的到期、protected 和 sticky 结束转 cooldown 按原版 WorldInfoTimedEffects 的区间规则移植，原版 `chat.length` 显式替换为该任务楼层时钟。

每次运行复制时序状态，扫描只写本次副本；只有任务真正成功才合并。提交时用短状态锁重新读最新记录：按 entry/effect 逐项合并；更新排序键为 `(settledFloor, sequence)`，sequence 表示准入次序，较旧楼层/较早准入运行不能覆盖较新成功记录，未改到的键保留。准入时从当前聊天所有任务历史、effect 与 tombstone 读取持久化序列高水位，脚本重载后同楼新运行仍获得更大序列。删除过期项也携带同一排序键的 tombstone，防止较晚完成旧快照复活已清理的 effect。lastSuccessfulFloor 取成功楼层最大值；常规链回滚按 ownerRunId 条件撤销自己的变动，不覆盖事件后续推进。该合并不改变已在途运行自己的候选池和扫描结果，符合允许读取中间状态的并发边界。

**原生预设、占位符和字段**

原生字段为 `prompts[].identifier/name/role/content/system_prompt/marker/injection_position/injection_depth/injection_order` 与 `prompt_order[].character_id/order[].identifier/enabled`。使用原版 OpenAI PromptManager 的 global strategy 顺序项 character_id `100001`；不按当前角色切到别的顺序，不把 prompt 数组顺序当作启用顺序。其他顺序项保留导出。缺少必需顺序或重复 identifier 报 invalid_preset，不借主聊天全局 PromptManager 补齐。深度消息按原版 depth/role/order 插入聊天副本，按原版预算分配保留提示词与历史；历史从最早开始裁剪，不拆半条消息。

| 标识 / 字段 | 运行处理 |
| --- | --- |
| main/nsfw/jailbreak/enhanceDefinitions 及用户自定义普通项 | 只取副本 content、启停、顺序、role 和 injection 字段；宿主角色卡覆盖不进入 |
| chatHistory | 本次 historySnapshot 与最终 task.prompt 用户消息；prompt 只插入一次 |
| worldInfoBefore/worldInfoAfter | 本次扫描 before/after 分区；空分区不补宿主全局结果 |
| charDescription/charPersonality/scenario/dialogueExamples | 自动角色卡内容为空；世界书放到示例分区的条目仍属于任务世界书输出，独立保留 |
| personaDescription / 作者注释 | 不自动填充；主动宏/模板读取不受影响 |
| 世界书 before/after author note、at depth、outlet | AN 分区通过模板上下文 `authorNoteWorldInfo.before/after` 显式读取；不继承主聊天注释锚点，也不自动改为 depth 0。at depth 按原版 role/depth/order 插入任务历史，同层同 role 合并换行；outlet 进入本任务 outlet 表，不写宿主 extensionPrompts |
| 采样 | raw.temp_openai→temperature；freq_pen_openai→frequency_penalty；pres_pen_openai→presence_penalty；top_p_openai→top_p；top_k_openai→top_k；openai_max_tokens→max_tokens；seed>=0 才发送 |

| 未识别 extensions | 保留导出；不自动调用其他扩展或注册全局行为 |

**同源后端精确载荷**

`fetch(new URL('/api/backends/chat-completions/generate', parent.location.origin), { method:'POST', credentials:'same-origin', headers:ctx.getRequestHeaders(), signal:task.controller.signal, body:JSON.stringify(payload) })`。baseUrl 是用户配置的服务 API 根地址，仅删除尾部 `/`；后端自行追加 `/chat/completions`，不能把完整 endpoint 再重复拼接。

```ts
const payload = {
  chat_completion_source: 'custom',
  custom_url: connection.baseUrl.replace(/\/+$/, ''),
  custom_include_headers: JSON.stringify({ Authorization: `Bearer ${taskSecret}` }),
  custom_include_body: '',
  custom_exclude_body: '',
  custom_prompt_post_processing: 'none',
  model: connection.model,
  messages: task.messages,
  stream: false,
  n: 1,
  temperature: preset.temp_openai,
  frequency_penalty: preset.freq_pen_openai,
  presence_penalty: preset.pres_pen_openai,
  top_p: preset.top_p_openai,
  top_k: preset.top_k_openai,
  max_tokens: preset.openai_max_tokens,
  ...(preset.seed >= 0 ? { seed: preset.seed } : {}),
};
```

原版 custom 分支先 readSecret(CUSTOM)，随后将 custom_include_headers 合并到 headers，最终 `{ Authorization: 'Bearer '+apiKey, ...headers }`。因此必须显式发送本任务 Authorization 头覆盖后端当前 CUSTOM 密钥，不能错误地传 `apiKey` 字段并假定原版接受。JSON 字符串是 YAML 的合法子集，不手工拼接多行凭据文本。空密钥也显式覆盖，避免无意继承宿主密钥。该字段仅随同源请求发送，不持久化/导出 payload。响应取 `choices[0].message.content` 文本；空白文本、缺少 choices、后端 error、错误 HTTP 均失败，不降级生成别的格式。

**EJS 阶段与上下文适配点**

`TaskMacros.substituteTaskMacros` 是独立生成的宏入口，供模板渲染（EJS 前后）、模板关键词匹配及原生世界书扫描共用。兼容 `{{get_message_variable::stat_data.世界.时间}}`，以及 message/chat/character/preset/global 五种作用域的 `get_*_variable`、`format_*_variable` 和 `format_*_variable_quoted`。通过宿主 `getVariables` 读变量，路径沿用 lodash 与 HTML 实体解码；字符串原样返回，其余值使用 JSON 或对应 YAML 格式，过滤递归 `$` 字段，缺失路径返回 null。消息默认读取当前聊天最后一个具有变量对象的消息及其当前 swipe，与助手生成宏语义一致，不强制使用任务目标楼层；preset 变量仍指宿主当前预设变量，不等同于任务导入的预设提示词副本。变量读取异常使本次生成失败，不发送未展开请求。不承诺执行 `registerMacroLike` 注册的自定义宏；其注册表不是公开调用接口。该兼容由独立任务负责，不依赖宿主全局生成事件触发。

公开接口是 `EjsTemplate.prepareContext(env, end)`、`EjsTemplate.evalTemplate(code, context, options)`；注意 prepareContext 内部在 env 合并后绑定默认 getpreset，因此必须在它返回后覆盖 `getprp/getpreset/getPresetPrompt`，并给兼容模板主动调用的 getPreset/getPresets 任务副本语义。按副本 name 精确/正则匹配提示词，调用任务 renderer 渲染；匹配方法遵原扩展 presets.ts 的 first find 行为，不借宿主当前预设。`generateData` 指向本次 messages，`runID` 用本次运行身份，`generateType:'normal'`，`runType:'generate'`，`isDryRun:false`。

为避免原始 getwi 自动附带宿主 WORLD_INFO 正则，任务覆盖 `getwi/getWorldInfo`，沿用原扩展的两种签名、缺省书选择和 first match 查询语义；只在此显式读取允许池外条目。读取文本交给同一任务宏/EJS renderer，并传 world_info/data，不调用原始 boundedReadWorldinfo；template 主动调用的 getchr 等仍允许当前聊天读取。

确定顺序：

1. 创建上下文与任务 helper，候选副本强制启用；用候选池选择 `[GENERATE:BEFORE]` / `@@generate_before`，按扩展 evaluateWIEntities 的 keyword/probability/order 条件渲染并收集 generateBefore。
2. 在任务候选副本处理 decorators：特殊条目从普通扫描集合移出但留在本次特殊条目池；@@if false 移出；`[Preprocessing]`/@@preprocessing 渲染 content 与 key/keysecondary；@@private 形成局部作用域包装；@@activate/@@dont_activate 只改任务内激活表，不调用宿主 activateWorldInfo。
3. 运行完整世界书扫描，组装任务预设与历史及深度/outlet 分区。
4. 遍历最终请求消息的 0-based idx：候选池 `[GENERATE:idx:BEFORE]` → 本消息显式任务正则和 EJS → `[GENERATE:idx:AFTER]`。generateBuffer 按已经处理的请求文本累积，generateData 保持本次消息数组。
5. 候选池 `[GENERATE:AFTER]` / @@generate_after 在全部消息处理之后执行；generateBefore 接第一条消息，after 接最后一条消息。随后处理候选池 @INJECT 的 pos/target/regex 指令与 role/order，使用扩展既定插入顺序；outlet 和临时注入都保存在本任务内。
6. 此时才冻结 payload 并发送 HTTP。模型返回后只执行任务 response 正则与输出提取，不再运行 GENERATE:AFTER。异常使任务失败，不沿用扩展 evalTemplateHandler 的 null 后静默保留原文路径。

不调用扩展 handler 中的全局 deactivateRegex、deactivateActivateWorldInfo、deactivatePromptInjection，不广播生成事件，不覆盖 STATE.isInPlace 等共享生成标志。prepareContext 依赖的共享变量读取属于已经接受的窗口风险，但任务预设、候选池与 messages 始终由上述任务上下文拥有。
