# 脚本发布准备契约

## 当前资料与入口

`src/MVU助手/release.json` 是当前发布资料的唯一来源，包含 `version`、`date`、`changes`。版本为不含前导零的三段正式版本（例如 `2.0.0`），日期必须是有效的 `YYYY-MM-DD`，说明为至少一条非空字符串。关于页当前版本与首条历史直接消费该文件，历史版本另行保留。

`pnpm release:prepare` 在构建前清理上次候选包并校验资料，读取 Git HEAD 与构建前工作区是否有未提交内容，再执行 `pnpm build` 并打包。资料或构建失败必须非零退出，不保留一个能被误认为本次成功的候选包。工具不会提交、推送、打标签或创建 Release。

## 候选文件

输出为 `dist/mvu-release/`：

- `index.js`：生产构建脚本，逐字复制，不重写代码。
- 对应 map：脚本确实引用 sourcemap 时，必须存在同目录的安全文件名对应文件；不允许远程或越出目录的引用。
- `release.json`：生成的候选资料与来源信息，见下例。
- `release-notes.md`：当前更新说明、源码基线、未提交状态（如有）与候选/安装说明。
- `SHA256SUMS`：其他包内文件的 SHA-256 摘要，不包含自身。

```json
{
  "version": "2.0.0",
  "date": "2026-10-17",
  "changes": ["本次更新说明"],
  "status": "candidate",
  "repository": "Malkuku/EraHelper-all-in-one-solution-for-ERA-scripts",
  "sourceSha": "完整的40位小写Git SHA",
  "sourceDirty": true,
  "files": {
    "index.js": "脚本的SHA-256",
    "index.js.map": "存在引用map时记录其SHA-256"
  }
}
```

`files` 只列脚本及复制的 map；元数据和说明由 `SHA256SUMS` 覆盖。`sourceDirty: true` 表示源码提交号只是基线，不能仅凭 SHA 完整还原未提交修改。元数据的仓库固定为正式源；使用模板 origin 或同仓库其他产品地址不能替代该身份。候选元数据不是客户端 latest 公告，没有远程下载 URL，不承诺该版本已对外发布。

## 工作流边界

`.github/workflows/prepare-mvu-release.yaml` 仅由 `workflow_dispatch` 触发，依次安装锁定依赖、运行确定性契约、构建/打包、上传 artifact；权限为仓库只读。必填字符串输入 `source_ref` 默认 `feature-erahelper-mvu`，直接交由 checkout 检出；工作流可从默认分支启动，但实际源码来自该输入。artifact 名含版本和候选 manifest 的 sourceSha，不能使用工作流分支的 github.sha 代替源码身份。GitHub Actions 自动附带的 artifact ZIP 只是候选下载，不作为固定 CDN 文件源。

旧 bundle 工作流可以按原分支范围构建并提交产物，但不再生成或删除版本标签。正式 Release、固定产物托管、版本公告、在线加载器与客户端更新属于后续范围。

离线验收权威入口为 `tests/release/prepare.mjs`，实际 Actions 和宿主加载须另外验证。
