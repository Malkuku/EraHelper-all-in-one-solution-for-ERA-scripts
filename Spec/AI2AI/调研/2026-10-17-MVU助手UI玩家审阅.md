# MVU 助手 UI 玩家视角审阅（2026-10-17）

## 结论与证据边界

当前界面已经恢复重要配置能力，但距离高标准玩家工具仍有明显差距：玩家需要自行记住任务触发规则、保存边界和目标身份；最重要的数据覆盖操作缺少足够的上下文保护。重构应优先解决“操作对象是否正确、修改是否保存、运行是否安全、失败后如何处理”，再统一视觉。

本报告为独立玩家/首次使用者视角的源码审阅，未在真实 SillyTavern 宿主运行。已读取现行架构、MVU 数据与版本契约、独立任务配置指南。实际查看了临时目录 `kat-ui-acceptance/api-binding-desktop.png` 和 `task-binding-mobile.png`，仅视为此前模拟宿主的历史截图，不能证明当前完整窗口或真实宿主行为。其余结论均来自明确源码证据；风险场景未伪称已端到端复现。

优先级：P0 为可能写错对象或覆盖玩家数据的发布阻断风险；P1 为明显阻碍正确配置或故障恢复；P2 为效率、可理解性及交互完整性问题。严重级别是审阅建议，最终由综合重构方案确定。

## 问题清单

### PL-01 · P0 · 变量编辑和版本更新没有锁定玩家正在操作的聊天与楼层

- 场景：在最后一楼打开变量编辑/更新预览后，新消息到达，或玩家切换聊天，再点击保存/执行。
- 证据：`src/MVU助手/stores/EraEditStore.ts:10` 从 `message_id: -1` 读取；`src/MVU助手/UI/view/EraDataEditor.vue:486` 加载后只保存数据副本，`EraDataEditor.vue:521` 保存整个对象。`src/Utils/MvuUtil.ts:48`–54 在提交时重新获取最后一楼并整体替换 `stat_data`。版本页初始化读取当前版本（`VersionUpdater.vue:196`），预览计算读取数据（`UseVersionControlStore.ts:260`），执行直接使用先前的 `finalData`（`UseVersionControlStore.ts:299`–307）。这两条路径没有任务内核现有的准入目标身份保护。
- 影响：界面中的“当前数据”可能已经不对应提交对象，旧快照可能覆盖新剧情变量。仅增加“是否保存所有更改”确认不能解决对象漂移。
- 改进：页面常驻显示角色/聊天、楼层及 swipe，加载时绑定身份和基线；提交前核对身份与数据版本。目标变化或数据被外部更新时保留草稿，停止提交并给出比较、重新加载的明确操作。版本预览同样必须过期失效。
- 验收：加载 A 聊天第 N 楼后分别追加消息、切至 B 聊天、切换 swipe、由任务更新同一变量；旧草稿/旧预览均不能写入新目标或覆盖外部变更；提示明确指出变化对象，草稿可恢复。

### PL-02 · P1 · 变量页草稿在刷新和跨页时容易静默丢失

- 场景：编辑一批变量，点击“刷新数据”，或去“更新版本”核对信息后返回。
- 证据：`EraDataEditor.vue:6` 直接绑定 `loadData`；`EraDataEditor.vue:483`–489 无 dirty 检查即覆盖 `currentData` 和 `originalData`；`Layout.vue:32` 使用普通 `router-view`，`Layout.vue:62` 直接切路由；变量草稿为页面局部 ref（`EraDataEditor.vue:289`），挂载即重载（`:704`）。
- 影响：玩家已看到“有未保存的更改”，仍可能通过看似安全的导航丢失修改；整个产品的草稿承诺不一致。
- 改进：统一变量编辑草稿生命周期；刷新、离开与关闭提供保存/保留/放弃语义，刷新读取失败时保留现有数据与草稿。任务配置页跨一级路由也应纳入同一策略。此处指 Layout 的一级路由卸载；TaskManager 内部 tab 共用草稿，不应误报为切内部 tab 即丢失。
- 验收：修改后刷新、切一级页、关闭再打开；每条路径都可明确保留或主动放弃，不能无提示丢失；失败重试后仍能取回草稿。

### PL-03 · P1 · “导出草稿”可能没有导出玩家刚输入的 JSON

- 场景：进入原始 JSON 模式修改数值，尚未切回树形视图，直接导出用于备份。
- 证据：`EraDataEditor.vue:334` 明确只验证 raw 输入而不更新 `currentData`；`EraDataEditor.vue:461`–466 的 `exportDraft()` 序列化 `currentData`，而保存使用 raw 字符串解析结果（`:519`）。
- 影响：导出提示成功但文件可能是修改前的数据，玩家误以为已备份草稿；这是保护数据操作中的错误反馈。
- 改进：树形/原始模式共用统一的当前有效草稿读口；raw 无效时清楚阻止结构化导出，并提供保留原始文本的明确方式。
- 验收：raw 模式改值后不切页直接导出，文件值与屏幕一致；无效 JSON 不得产生冒充有效草稿的旧文件。

### PL-04 · P1 · 运行结果把故障恢复信息藏在折叠层级里

- 场景：自动任务失败并发生回滚失败，玩家只想知道剧情/世界书是否已被改动、是否需要处理。
- 证据：`AsyncAnalyze.vue:25` 默认折叠每次运行，summary 仅显示总体状态和楼层；回滚状态、错误与警告位于其内部（`:32`–36），每任务信息再次折叠（`:37`）。运行区域没有空状态引导（`:12`–53）。
- 影响：玩家可能把“失败”理解为“没有改动”，漏看残留修改；技术 ID、错误 phase/code 比下一步行动更显眼。
- 改进：运行列表第一层直接展示“已写入/已撤销/仍有残留”的状态；回滚失败与部分完成自动展开并保留醒目提示。提供目标定位、复制诊断和针对原因的下一步，区分新手摘要与技术详情。
- 验收：模拟生成失败无写入、成功写入后回滚完成、回滚部分失败三类结果；无需展开即可区分数据状态，玩家能直接找到受影响目标及恢复建议。

### PL-05 · P1 · 手工运行和重算缺少操作前的目标及后果摘要

- 场景：玩家刚修改任务草稿，跳到运行结果点击运行；或把“回滚后重新计算”当普通重试。
- 证据：`AsyncAnalyze.vue:14`–16 三个动作同等呈现；`:87` 的手工运行立即取最后楼层执行；没有按钮附近的目标任务、写入范围、草稿使用状态和会话日志限制提示。顶部已保存配置说明存在（`TaskManager.vue:3`–14），但运行操作处没有闭环说明。
- 影响：运行旧配置产生付费请求与写入；重算撤销旧提交与普通再运行的差别需要玩家靠文档记忆。
- 改进：操作区显示当前聊天/楼层、已保存配置版本和会运行的任务；有草稿时显式提示本次使用已保存配置。重算说明将撤销哪条常规链、日志是否可用及失败原因；清空结果明确只清显示。避免每次普通运行添加泛化弹窗。
- 验收：存在未保存草稿、没有活动任务、缺失回滚日志及已有可回滚链时，按钮状态与说明都能预测实际动作；玩家不会把清空结果理解为撤销。

### PL-06 · P1 · 任务基础参数隐藏了会改变执行阶段的关键语义

- 场景：玩家为了让任务排在最前，填写执行顺序 -1；或填写事件名后认为任务只通过事件执行。
- 证据：`TaskManager.vue:457`–461 仅给出“附加事件名”“执行顺序”等输入，没有解释负顺序发送前执行、同序并发以及事件仍属于常规链。现行指南“创建任务”和“前端或脚本触发事件”明确了这些规则。
- 影响：任务意外在发送前运行，或事件任务自动重复运行；玩家需要依赖外部长文档才能正确预测行为。
- 改进：在基础区直接显示根据当前参数推导的触发摘要；执行阶段使用明确可理解的表达，顺序与并发关系可预览；事件字段说明其为附加入口。保留现行业务规则，不擅自改变值语义。
- 验收：对 order=-1、0、同序多任务、事件名非空分别检查摘要；首次使用者能在界面内判断触发时机、并发关系及是否进入常规链。

### PL-07 · P1 · 版本检查可能把规则错误呈现成“无需更新”

- 场景：卡作者的一个版本更新块 JSON 错误，玩家检查升级。
- 证据：`UseVersionControlStore.ts:122`–136 逐块解析后仅记录控制台错误并跳过，`:139` 用剩余块计算目标版本；没有剩余更新时 `:265`–267 显示“当前已是最新版本，无需更新”。`VersionUpdater.vue:202`–206 初始化读取失败也只写控制台。
- 影响：玩家无法区分“确实最新”“找不到规则”“规则损坏”与“读取失败”，可能在不完整规则集上升级。
- 改进：检查状态必须区分未检查、检查中、最新、有更新、来源不可用和规则错误；显示错误块及版本，损坏规则不得被静默当作成功检查。提供刷新来源与重试，保留上次有效信息但标记过期。
- 验收：空条目、部分 JSON 损坏、全部损坏、世界书读取拒绝分别得到不同且可行动的界面结果；不能出现错误发生却宣称最新。

### PL-08 · P2 · 版本更新审查流程点击很多，却不能对照旧值与新值

- 场景：玩家升级大量变量，需要确认角色金钱、关系和背包如何变化。
- 证据：`VersionUpdater.vue:90`–128 按删除/更新/新增分四步揭示；更新区只传 `diffData.updated`；`UseVersionControlStore.ts:249`–250 只存新值。最终区域只有覆盖警告，未展示最终数据。`VersionUpdater.vue:180`–186 要求顺序点击推进。
- 影响：连续点击制造审查完成感，但缺乏判断关键变更所需的原值与路径；空差异类别也占步骤。
- 改进：一次展示按路径排列的变化，明确旧值→新值及新增/删除数量；可搜索和折叠，关键变更可定位。危险确认建立在具体影响摘要上，而非只完成步骤计数。
- 验收：包含删除、数组覆盖、标量修改、嵌套新增的更新，均能直接比对；无变化类别不要求无意义点击。

### PL-09 · P2 · 世界书“已停用”和“已勾选”容易被理解为实际发送结果

- 场景：玩家选中停用条目后担心不会使用，或看到已勾选 20 项就认为模型会收到 20 项。
- 证据：`WorldbookPicker.vue:18` 显示勾选数量，`:32` 显示源条目启停及名称正则命中；这是源状态与候选选择状态。现行架构和指南明确任务副本强制启用，但仍须经过完整扫描；任务页标题只有“任务世界书候选池”（`TaskManager.vue:477`）。
- 影响：常见误配会被当成模型故障，玩家无从区分候选、扫描命中与最终发送。
- 改进：在选择处解释源启停状态不限制本任务候选、副本不修改原书；分别显示手选/正则/并集候选数。运行详情能够解释实际采用和未采用的原因；不可把静态名称匹配预览宣传为完整扫描结果。
- 验收：停用但手选、仅正则命中、二者重叠、预算淘汰四种场景，显示清楚且不重复计数、不误称已发送。

### PL-10 · P2 · 产品要求小窗口完成复杂配置，但现有信息占用与导航语义过重

- 场景：玩家在笔记本或手机上反复切换 API、预设、任务、规则组，返回原任务继续配置。
- 证据：宿主 `Layout.vue:95`–106 限制桌面宽 680px 且最小高 750px；`TaskManager.vue:3`–42 在内容前叠加当前生效列表、五步入口、八项 tab 和工具栏。历史桌面截图为 1200px 独立内容视图，不能证明 680px 实际宿主窗口下可用性。父 Agent 补充的当前 Layout + TaskManager 模拟宿主结果：1024×600、768×600 的 card y=-75、高 750，顶部导航被裁掉且关闭键部分裁掉；证据为临时目录 `kat-ui-review-20261017/metrics.json` 和 `shell-1024x600.png`，由父 Agent 目视核实，本审阅者未独立运行。该确定性可达性问题应升为 P1，并由综合报告单独列项。历史移动任务截图可见“配置已保存”与顶部“草稿尚未生效”同时出现；源头是持久化 `notice`（`TaskManager.vue:934`）与独立 dirty 状态（`:6`），成功提示没有随新修改消退。
- 影响：有效编辑空间减少；“规则组/规则/任务”混合命名增加寻找成本；旧成功提示与当前脏状态并存，使玩家不确定最后一次操作是否已生效。
- 改进：按玩家任务重组主导航，明确区分任务库、组合和运行；生效概览可折叠并保持必要状态；保存状态只反映当前草稿。按真实宿主宽度验证布局，不以宽屏组件截图代替整体窗口验收。
- 验收：实际完整窗口在 390×844、680×600、1366×768 及 200% 缩放可操作；任务深度编辑时主要操作可达；新修改后不继续宣称当前内容已保存；从 API/预设返回可以恢复原任务上下文。

## 玩家侧重构门禁

1. 数据安全：PL-01 的目标身份、外部变更和过期预览保护先完成，禁止仅用确认框替代。
2. 草稿可信：保存、导出、刷新、切页和关闭共享同一草稿事实；当前状态无矛盾提示。
3. 行为可预测：触发时机、任务来源、候选与实际输入、运行写入范围可在操作附近判断。
4. 故障可处理：错误、取消、回滚和部分残留能直接区分，具备可操作恢复说明。
5. 验证充分：独立验收覆盖实际完整窗口和真实宿主；本报告未执行这些场景，不能把问题建议当成已验证修复结果。
