## 审阅结论与证据边界

## 问题清单

### D01：实际外壳约束与内部响应式模型冲突（P1）

- 证据：`src/MVU助手/UI/view/Layout.vue:95` 最大宽 680px，`:102` 最小高 750px，同时最大高 90dvh；`:133` 再扣 24px 内边距。`src/MVU助手/UI/components/AsyncAnalyze/TaskManager.vue:1503` 左栏固定 220px，`:1624` 却按宿主视口 768px 切换分栏。
- 可信度：A + R。本轮模拟宿主在1024×600、768×600直接复现导航裁切（card y=-75、height=750），截图可见关闭按钮部分被裁；大屏上的小容器仍使用桌面分栏。375×812本轮未观察到 body 横溢出，不能泛称所有移动尺寸均溢出。1100px 编辑弹窗不能反向证明主工作空间可用。
- 影响：表单被压窄、多层滚动、低高度窗口关闭或操作区可达性风险；大屏空间未用于编辑。
- 重构要求：建立 AppShell 的尺寸权威，以实际容器宽度决定列表/详情布局；外壳使用受视口约束的高度和 `min-height:0`，桌面提供宽工作空间，小屏转单页导航。
- 验收：完整 App 在 390×844、667×375、768×600、1366×768、1920×1080 以及 200% 缩放逐一验收；无页面级横向溢出，关闭与主操作可达；除代码/JSON 局部区域外，每个工作区仅一个主纵向滚动容器。

### D02：导航分层混乱，新手路径与日常工作相互挤占（P1）

- 证据：`Layout.vue:6` 四个顶级导航中有低频“版本信息”；`TaskManager.vue:16` 五个常驻设置步骤，`:23` 八个二级标签，`:725` “规则组选择/规则组配置/规则编辑”并列。步骤要求先预设，但标签先 API，词汇也混用任务与规则。
- 可信度：A；历史截图 C 支持首屏多排导航与工具栏堆叠。
- 影响：用户必须先理解内部配置关系，无法直接按“现在运行什么、改哪个任务、出错怎么办”行动。
- 重构要求：主导航按任务心智组织，合并规则组选择与管理；预设/API/正则归为资源管理；首次设置用可恢复检查清单，已完成后折叠。“关于”降为工具菜单。
- 验收：首次建成一套可运行配置有明确下一步与完成状态；已配置用户打开后可直接看到活动组及运行入口；任何一级页面都有唯一名称与当前定位，任务入口统一称“任务”。

### D03：切换主功能缺少草稿生命周期保护（P1）

- 证据：`TaskManager.vue:711` 草稿仅存在组件局部 ref；`Layout.vue:32` 普通 router-view，`:62` 直接路由跳转。`UI/router/router.ts:8` 分步配置、变量编辑与更新页为不同路由；当前 UI 没有路由离开保护或 KeepAlive。变量编辑也使用局部 `currentData`（`EraDataEditor.vue:289`）。
- 可信度：A（实现结构）；路由往返导致具体输入消失需 B 验证。关闭 Layout 的 v-if 也应纳入同一验收。
- 影响：用户跨到变量编辑查资料、关闭再打开时可能丢失配置或变量草稿；与“切页保留编辑”的用户预期冲突。
- 重构要求：明确配置与变量两种草稿各自的生命周期；跨功能保留草稿，丢弃必须显式；退出、刷新、导入、撤销统一执行草稿保护。不能用每次切标签都弹确认替代合理保存状态。
- 验收：分别修改任务提示词、本地密钥、变量值后，切换三个主功能并往返、关闭再打开，修改仍在且未误生效；显式丢弃才恢复已保存值。重载是否恢复草稿必须给出明示承诺并据此验收。

### D04：“保存当前任务”的视觉位置实际提交整个配置（P1）

- 证据：`TaskManager.vue:35` 顶部“保存配置”，`:647` 任务弹窗同名按钮都调用 `save()`；`:921` 校验完整配置，`:922` 保存整个草稿。`:936` 将失败合并成一条全局文本。保存任务时其他未完成 API/预设也参与校验。
- 可信度：A。
- 影响：编辑一个任务可能提交其他页面改动，或因不可见页面缺失字段而失败；长错误文本无法帮助定位修正。
- 重构要求：保留全局配置事务语义，但用统一固定保存栏，明确“保存全部更改”和受影响实体；实体面板动作不制造局部提交假象。把 schema 错误转为可点击的问题清单和字段错误。
- 验收：同时修改两个 API 和一个任务时，保存前可看清范围；故意填错预设预算与任务字段，能从错误摘要一键跳到正确实体、分区和输入框，修正后一次保存成功。

### D05：常驻完整生效配置会随任务规模吞噬首屏（P2）

- 证据：`TaskManager.vue:10` 对已保存活动组全部任务逐项输出名称与 API/模型/预设，`:16` 后又绘制五步引导；无折叠或数量摘要。
- 可信度：A；一任务历史截图 C 已展示明显头部占用，十任务表现仍需 B。
- 影响：越成熟的配置越难到达编辑区域，小屏主要在反复滚动公共头部。
- 重构要求：常驻一行活动组、任务数量、已保存/草稿状态；详情按需展开，保留生效与草稿明确区分；首次引导独立折叠。
- 验收：1、10、30 项任务时公共头部高度不线性增长；未展开详情也能明确当前生效组，发现未保存修改，并进入任务编辑或运行。

### D06：任务表单缺少基于意图的基础与高级分层（P2）

- 证据：`TaskManager.vue:457` 事件名、执行顺序、历史条数、触发间隔、重试同级铺开，提示词在 `:473`；`:531` 多项扫描参数和 `:537` 开关仅作字段集合。
- 可信度：A。
- 影响：新手先面对工程参数，任务的“何时执行、读什么、产出什么”不清；高级用户也缺少配置摘要。
- 重构要求：任务详情按“基本与提示词、触发、输入来源、输出、调试”分区；用人话解释顺序正负值、并发组、事件额外入口，底层数值放高级区。不能擅自改变负序发送前、非负接收后等现行业务规则。
- 验收：关闭高级区仍能配置普通任务；配置发送前、接收后与附加事件三种入口时，摘要准确复述真实触发关系；用户不用查指南即可判断 0 历史、间隔及重试的作用范围。

### D07：API/预设具备绑定能力，但可执行性与影响范围没有统一状态（P2）

- 证据：`TaskManager.vue:205` 连接字段、`:214` 绑定预设、`:260` 引用任务分散展示；`ConnectionCheck.vue:8` 准确声明只检查 /models，此能力应保留。`TaskManager.vue:1016` 新建预设直接弹上下文 Token 数，`:316` 八项采样参数同级输出。
- 可信度：A。
- 影响：用户易把资源存在、已保存、模型接口通过、任务生成成功理解成同一个“可用”；初次创建预设从技术参数开始，缺少用途与名称。
- 重构要求：连接详情分别呈现草稿状态、绑定完整性、最近模型接口检查及任务运行证据；预设先给名称/用途/上下文与回复预算，再渐进展开采样和高级注入；编辑绑定前就展示受影响任务。
- 验收：接口成功但生成失败时，页面同时准确保留两种事实；未绑定预设和未选模型可在资源列表识别；修改共享绑定可预先看到全部受影响任务，不误称已经生效。

### D08：世界书“选中、候选、激活、最终发送”缺少清晰表达（P2）

- 证据：`WorldbookPicker.vue:18` 只统计手勾数量，`:33` 另标记正则命中及宿主停用状态；任务页 `TaskManager.vue:737` 名为“任务世界书提取”，但实际是候选池与扫描。已有说明明确加入候选不保证发送，应保留。
- 可信度：A；历史世界书截图 C 可见“已停用”与“名称正则命中”并置。
- 影响：用户可能以为未勾选的正则命中项没被选中，或以为宿主停用会使本任务候选不可用；也可能误把候选数量当发送数量。
- 重构要求：统一称“输入世界书”；分开显示手选、名称匹配、去重后的候选集合；宿主状态与任务副本状态分开说明。最终激活数量只在拥有真实运行证据时展示，不能模拟推算冒充运行事实。
- 验收：手选与正则命中重叠、两者皆空、宿主禁用、已选 UID 不可用四组样例，候选来源和保留状态准确可见；用户可明确判断“候选不等于最终发送”。

### D09：正则测试器存在多层保存与应用语义负担（P2）

- 证据：`RegexWorkbench.vue:32` “更新配置/存入正则库”，`:63` “应用回当前字段”，`:67` 再要求全局保存；`:56` 可切换显式正则/目标字面替换语义，字段来源没有常驻路径标识。
- 可信度：A。
- 影响：用户分不清修改了临时测试值、库草稿还是任务字段，离开测试器时难判断完成程度。
- 重构要求：标题持续显示调用来源，如“任务 A > 输出 > 写入 1 > 提取正则”；明确区分“加入库草稿”和“应用到任务草稿”，全局保存独立。按当前用途默认展示匹配/提取/替换所需信息，允许高级切换但不能静默改义。
- 验收：从世界书名称、响应提取、目标替换三个入口进入并返回，来源与应用范围始终可见，测试语义与生产一致；保存/导入/撤销导致字段关联失效时有明确提示且不能错误应用到旧字段。

### D10：运行结果藏于配置导航深处，诊断优先于玩家行动（P1）

- 证据：`TaskManager.vue:731` 运行结果是第七个配置标签。`AsyncAnalyze.vue:19` 在途仅显示链/楼层/ID，`:25` 完成结果两层 details，`:29` 先给 requestId/runId，`:45` 错误展示 phase/code，`:51` 生成文本缺少复制操作。
- 可信度：A。
- 影响：玩家难知道“正在做哪件事、有没有写进去、失败后应做什么”；忙碌、取消、回滚失败与普通失败的后果区别不明显。
- 重构要求：运行记录独立为主功能；在途提供当前任务及取消，结果首层以状态、楼层、任务名、写入/回滚结论和下一步为中心；ID、原始错误和技术细节收进诊断区。无法从内核取得的进度不得伪造百分比。
- 验收：成功、仅返回、busy、跳过、取消、写入失败、回滚失败七类结果，第一层即可判断是否写入及是否仍有残留；生成内容一键复制；运行失败可返回相关任务/连接修正。

### D11：运行、回滚重算和清空记录使用相同操作权重（P1）

- 证据：`AsyncAnalyze.vue:14` 三个按钮相邻，“回滚后重新计算”直接绑定内核方法，`:88` 清空只改变结果列表。当前页没有在重算触发前常驻解释当前楼层、可用会话日志和影响范围。
- 可信度：A；内核已有严格日志边界，不应误报为任意覆盖。
- 影响：高后果操作与普通显示操作并排，用户无法预先判断它会撤销哪次提交，也可能把清空视作撤销结果。
- 重构要求：普通运行作为主动作；重算作为独立高后果操作，展示绑定楼层、上一条可回滚链、会话限制与不可用原因；清空归入记录工具并明确只清显示。
- 验收：无日志、有成功历史但重载、可回滚、回滚冲突四种情形有准确预检查或错误说明；重算前能看到作用对象；清空显示后不改变任务状态或已写数据，页面有清楚反馈。

### D12：变量编辑缺少写入目标身份，刷新与草稿导出存在信任风险（P1）

- 证据：`EraDataEditor.vue:6` 刷新直接 `loadData`，`:488` 无条件替换草稿；`:513` 保存确认仅“是否保存所有更改”。`stores/EraEditStore.ts:10` 读取当前最后消息，`:22` 通过 last-message helper 保存，页面未展示绑定聊天/楼层/swipe。`EraDataEditor.vue:334` raw 输入仅校验不更新 currentData，`:466` “导出草稿”却导出 currentData。
- 可信度：A（直接替换和导出对象）；跨聊天错误目标属于 B 风险，需要专项宿主验证，不能据静态审阅声称已错误写入。
- 影响：有修改时刷新可直接丢草稿；原始 JSON 编辑中导出可能得到旧树数据；保存时玩家不知道覆盖哪个消息的变量。
- 重构要求：持续展示当前聊天/消息/swipe 与数据快照时间；刷新前保护草稿；导出以当前编辑源为权威，非法 JSON 可导出原文本恢复；保存展示差异和目标。跨聊天或外部变化应阻止盲目覆盖，具体目标绑定需与数据契约同步设计。
- 验收：raw 改值未切树视图就导出，文件含修改；非法 raw 不冒称导出成功新对象；树/raw 草稿刷新都需可恢复；编辑期间切聊天、换 swipe、新增消息后保存，不可无提示写到另一个目标。

### D13：版本更新预览强制逐段点击，却缺少旧值对比和稳定失败停留（P1）

- 证据：`VersionUpdater.vue:89`、`:100`、`:111` 通过 reviewStage 逐段显示删除/更新/新增，`:182` 至 `:186` 四次推进；`:105` 更新字段仅树展示。`:250` 原生 confirm，`:251` 执行后无条件返回首页；`UseVersionControlStore.ts:312` 捕获错误只 toast，不重新抛出。`:54` 和 `:60` 将版本 toFixed(1) 显示，而契约版本为数值。
- 可信度：A。
- 影响：点击步骤并不证明理解差异；失败后预览退出，用户难修正重试；例如版本 1.04 会被显示为 1.0，无法准确判断更新跨度。
- 重构要求：一次展示变更数量、受影响路径与旧/新值，可按新增/修改/删除筛选；确认区展示聊天/消息及精确版本；执行状态持续留在页内，失败保留预览和重试条件，成功后才更新完成态。
- 验收：空差异、大量差异、1.04→1.05、执行失败四组场景，摘要与版本精确；失败保留已审阅上下文及错误；最终确认前可以看到实际变更而无需连续点击空步骤。

### D14：弹层和导航缺少完整键盘与读屏语义（P1）

- 证据：`Layout.vue:2` 外壳无 dialog 语义；`TaskManager.vue:422` 虽有 dialog/aria-modal，但未见焦点约束、关闭恢复或 Escape；`CustomModal.vue:4` 无 dialog 名称关联，`:42` 仅 prompt 聚焦。`TaskManager.vue:24` 标签切换未提供 aria-selected/面板关联；`EraDataEditor.vue:165` 字段 label 与输入无显式关联。
- 可信度：A（缺少明确实现）；宿主可能注入的行为及具体读屏效果为 B，不能替代组件责任。
- 影响：键盘焦点可离开模态层、返回位置丢失；选中导航和错误字段对辅助技术不清楚。
- 重构要求：统一 Dialog/AlertDialog、导航和字段组件：可访问名称、初始焦点、Tab 焦点范围、Escape、关闭恢复；背景在模态时不可交互；标签页或导航语义择一完整实现；错误使用 aria-describedby 关联，异步反馈适度播报。
- 验收：仅键盘完成创建连接、选预设、改任务、世界书选择、保存、处理错误、取消运行；关闭弹层回到发起按钮；读屏能识别弹层标题、当前页面、输入名称及错误，不连续播报整页日志。

### D15：视觉系统与操作密度缺少跨页面统一标准（P2）

- 证据：`Layout.vue:93`、`:187` 多层渐变与阴影，`:220` 导航 11px；`:329` 移动导航 10px 再缩至 0.9；`:233` 外壳操作按钮 28px。`TaskManager.vue:1190` 起已有局部色彩变量，但 Layout、AsyncAnalyze、变量和版本页继续各自硬编码；`AsyncAnalyze.vue:127` 使用 !important 处理宿主控件配色。
- 可信度：A；历史截图 C 支持整体偏表单堆叠与字号层级弱。未实测对比度，不声称具体不达标比值。
- 影响：主题与状态表达不稳定；微小导航和小触点降低可读性；过多同形描边按钮使主次不明，宿主样式干扰容易触发局部补丁。
- 重构要求：建立共享语义 token（背景/层级/正文/次文/边框/品牌/成功/警告/危险/焦点）、字体层级、间距、控件尺寸和按钮层级；克制使用阴影；统一图标体系，图标不替代文本；深浅主题由同一语义映射，隔离宿主样式。
- 验收：建议正文 14–16px、辅助文本不小于 12px；触控主目标至少 44×44 CSS px，可见焦点明确；两种主题逐页实测文本与交互状态对比度；成功/错误/禁用/选中均同时具有文字或形状，不能只靠颜色。

## 目标信息架构与关键页面

以下为重构提案，不宣告替代当前 Spec，实施前须由主任务确认和登记。

一级工作空间建议为：**概览、任务与规则组、运行记录、资源、变量、数据更新**；“关于/版本信息、主题”移入全局工具。保持现有能力、内核与配置关系，优先改变组织与呈现。旧版“分步配置”可作为工作空间名称，避免把原页面标签原样搬成新侧栏。

| 页面 | 首层必须回答的问题 | 关键结构 |
| --- | --- | --- |
| 概览 | 当前运行哪组？配置是否完整？最近失败是什么？ | 活动组摘要、草稿状态、配置检查清单、最近运行、主运行入口 |
| 任务与规则组 | 哪个任务属于哪个组？改动影响什么？ | 组筛选/选择、可搜索任务列表、任务详情；详情有名称状态/触发摘要、分区表单、影响范围；启用组与管理组在同一上下文 |
| 运行记录 | 是否完成和写入？要取消、修正还是重算？ | 在途区、结果列表、状态过滤、结果详情、写入/回滚摘要、诊断折叠、复制结果 |
| 资源 | 哪些 API/预设/正则被哪些任务使用？ | API/预设/正则库二级导航、列表/详情、引用关系、明确的接口检查证据；世界书在任务内选择，资源页可提供浏览入口但不创建第二套选择状态 |

AppShell 结构：顶栏保留产品名、聊天上下文、主题与关闭；宽空间使用持久导航及列表/详情；窄空间使用功能入口→列表→详情的单列返回层级。统一保存栏持续呈现全局配置草稿，变量保存与版本更新独立声明作用对象，不将三种持久化语义混成同一个“保存”。

## 组件设计原则

1. **一个状态一个权威来源。** 生效配置、配置草稿、测试临时值、运行终态、变量草稿分别清楚命名；界面可以摘要，不能复制另一套业务判断。配置 API 绑定预设、候选池扫描、回滚日志限制仍消费既有内核事实。
2. **页面负责意图，组件负责一致交互。** 建立 AppShell、PageHeader、Navigation、SaveBar、FormField、ErrorSummary、StatusBadge、EmptyState、ListDetail、Dialog、ResourcePicker、RunResult；不为了“设计系统”先包一层全部原组件而保留所有旧样式职责。
3. **每个动作说明范围与结果。** “应用到草稿”“保存全部配置”“清空显示”“回滚此链后重算”使用不同词；成功、失败、空、加载、过期、不可用均有状态与可行动反馈。
4. **普通路径短，高级能力可发现。** 先提示词/来源/结果，再展开参数；高级折叠不能隐藏当前生效的异常配置、危险写入或错误。
5. **组件按容器响应。** 列表/详情根据可用空间切换，不以屏幕宽度假定嵌入面板宽度；局部 JSON/代码滚动不能扩大整个页面。
6. **用真实数据证明界面。** 已选候选、最终激活、请求完成、持久化完成、回滚完成各自有独立事实；无真实进度数据就展示活动状态而非百分比。
