## 验证边界与证据规则

### 用户决定补充场景（G0 前冻结输入）

以下来自协调 Agent 转交的用户确认，不从实现推导；尚未执行测试。

- A6：`enabled=false` 的任务在自动、手动、显式事件入口均不执行并返回明确跳过原因。自动间隔不满足时常规入口跳过，同一任务显式事件仍可执行；同聊天常规链第二次触发立即 busy。busy 键验证脚本 + chat + event 的隔离；切聊天取消原运行，原运行迟到响应及等待提交锁后的响应都不得写入原/新聊天或推进时序状态。
- A3/A6：时序以 task + chat 隔离；成功结算推进，生成成功但提交失败、取消及重试中的失败尝试均不推进。两个同 task 在途运行按 G0 明确的结算合并规则验证，不允许最后返回的旧快照回退已成功状态。
- A6：正文最小长度是可配置值，默认 300，适用于 MESSAGE_RECEIVED 自动常规入口。默认阈值下验证 299/300/301；修改阈值后验证阈值前一位/等于/后一位；显式事件对短正文仍可执行。字符计数口径、0 楼保护及其他入口范围由 G0 明文确定，测试不得自行假定。
- A4/A9：主聊天全局/角色正则即使匹配任务文本，也不改变任务请求/结果；显式任务正则与模板按已声明阶段处理。配置重载后默认及修改后的最小长度值正确保存。
- A1/A4/A5：玩家人设与作者注释不自动加入请求，personaDescription 占位符及作者注释自动来源须为空；宿主这两项非空时同样验证。另以显式宏/模板读取相同内容，必须可用并仅出现在任务模板指定位置；任务世界书自身 before/after author note 分区仍独立保留，不因禁用自动作者注释而误删。
- A7/A8：世界书输出目标不存在时自动创建且启用；已有目标须按 book + UID 写入。覆盖同名不同 UID 条目、不同书同名、同一不存在目标的并发创建，核对目标身份和去重规则，不允许按名称“取第一个”或静默改写别条目。名称解析/并发创建去重的具体规则由 G0 冻结。
- A8：创建后发生常规链失败，回滚只撤销本运行拥有且仍可安全逆转的创建；若另一运行已修改该新条目，不得直接删除，须保留其他运行数据并报告 rollback conflict/残留；创建失败或启用保存失败须算任务失败，不能仅因取得 UID 报成功。不同 UID 的独立事件写入在回滚后保留。
- P3 准入反例：合法事件名 `regular` 与常规链同时运行，两者不得因内部字符串 key 碰撞互报 busy；同聊天两个重算或重算撤销期间自动入口触发，准入保护必须覆盖 undoRun 阶段，不能重复撤销同一日志或交错执行新链。
- P3 终态关联：调用方已取得的 RunResult、结果事件载荷及缓存记录应表示该次触发终态；后续重算/撤销不得因复用 journal.result 引用而悄悄改写旧结果。应保留独立快照，重算结果再表达本次撤销与新执行情况；若实现采用其他可观察语义，先明确契约，不能默认可变终态。

默认确定性测试不得发起付费模型请求或依赖外部服务。发送层使用可控响应与屏障验证真实组装载荷和交错次序，不用固定 sleep 推断并发。取消、错误、忙碌、冲突和部分失败均验证具体结果，而非仅断言最终 success。

宿主验证独立登记版本、入口、fixture、观测载荷与结果。构建、类型检查和 mock 测试不能替代宿主后端鉴权、EJS、宏、实际扫描及 MVU 的集成证据。没有宿主时记录“未验证”，总体门禁停留待验收。只读检查连接或工具能力不等于集成已通过。

G0 所需的 schema、事件字段、作用域/重入/间隔、扫描状态、支持矩阵、目标与回滚所有权和后端载荷已按目标契约补齐；实际宿主支持版本仍需现场证据，不据源码基线宣称已部署验证。
