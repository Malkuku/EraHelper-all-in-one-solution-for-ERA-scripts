# CDN加载器独立验收

## 验收依据与独立风险矩阵

2026-10-18：测试Agent先读取CDN加载与更新契约、迭代任务及测试治理规则形成下表，再读取实现。不以实现自测结论作为验收依据。

| 风险 | 应证明的行为 | 验证责任 |
| --- | --- | --- |
| 地址或版本描述被污染 | 公告严格校验；只从固定仓库、40位产物提交、合法版本构造地址 | 加载器契约行为 |
| 普通重启静默升级或离线失效 | 首装选latest，后续使用完整已保存描述，公告失败不阻断选定版本 | 加载器持久化行为 |
| 下载损坏或失败执行代码 | 摘要不符与HTTP失败零执行；管理入口可达并可重试 | 加载器行为与浏览器模块fixture |
| 重试重复产生副作用 | 当前iframe最多执行一次，执行失败只能重载 | 加载器行为与浏览器模块fixture |
| 更新期间任务启动 | 异步下载和确认后再次检查忙碌，忙碌零写入零重载 | 加载器与核心桥接 |
| 缓存刷新显示假成功 | 官方刷新需验证码时打开官方页，展示公告地址与未清缓存事实；HTTP/格式失败明确反馈，旧公告不称已更新，不自动切换 | 加载器公告行为 |
| 破坏宿主身份与数据 | 核心在原iframe运行，script ID不变，仅写加载器自己的存储键 | 浏览器模拟宿主 |
| stage接受脏/损坏候选或覆盖历史 | 校验来源、摘要与完整候选，已有目录拒绝，stage不写公告 | 发布工具临时Git fixture |
| source SHA误作产物SHA | announce用实际包含产物提交，source SHA与产物SHA不同仍正确 | 发布工具临时Git fixture |
| CDN字节未就绪先公告 | Git文件和CDN核心/元数据匹配后写公告，失败保持旧公告原字节 | 发布工具临时Git fixture |
| 历史版本重指或丢失 | 保留历史版本，同版本变更提交/内容拒绝 | 发布工具公告行为 |

## 测试归属与环境边界

发布准备继续复用 `tests/release/prepare.mjs`。新增加载器与分发测试放在同一权威目录，职责分别覆盖客户端运行和本地stage/announce，不复制候选准备测试。

浏览器fixture只模拟宿主API与CDN响应，必须实际执行ES模块；真实GitHub/jsDelivr、跨源生产依赖、酒馆生命周期与真实任务仍是外部门禁。验收过程不提交、不推送、不发布。

## 独立验收结果

2026-10-18，本地确定性与模拟浏览器验收通过：

- `node tests/release/prepare.mjs`：44组；原42组回归，加版本号、源码SHA尾换行反例；同一权威入口增加分发测试CI门禁及加载器候选artifact来源身份检查。
- `node tests/release/distribute.mjs`：20组；临时Git仓库生成真实候选并提交版本文件。覆盖stage完整字节复制、dirty/摘要损坏/缺文件/覆盖拒绝，announce产物提交与源码提交不同、错误提交拒绝、核心及元数据CDN字节核对、网络/HTTP/内容失败公告原字节保持、同版本重指拒绝、历史保留与写锁并发保护。无外部网络与发布操作。
- `node tests/release/loader.cjs`：13组浏览器运行契约与DOM/iframe交互。实际Blob ES模块执行，覆盖首装、重启固定版本且不读取公告、HTTP/摘要/网络失败零执行、失败可达、重复执行拒绝、部分执行后换版重载恢复、忙碌阻断及下载/确认后竞态复核、并行apply拒绝、取消保持、公告损坏和旧缓存说明、危险描述拒绝。
- DOM fixture实际执行加载器入口，在原iframe中导入小核心模块；检查失败时父页版本管理、官方刷新页/验证码/公告地址与HTTP失败说明、原script ID、script域存储、只写选版键、原配置与密钥不变、既有脚本按钮保留和375宽度布局。下载失败后修复响应、应用选版，真实iframe完成第二次启动后才执行核心，当前iframe不原地重执行。

生产加载器使用同一入口复验：

```powershell
$env:LOADER_BUNDLE = (Resolve-Path 'dist/MVU加载器/index.js').Path
node tests/release/loader.cjs
Remove-Item Env:LOADER_BUNDLE
```

最终生产加载器（含失败恢复与状态中文）已完成DOM/iframe复验，13组运行契约与上述生产入口交互通过。三个发布测试文件定向ESLint为0 errors；仅Node内置模块与可配置Playwright路径的18条规则warnings。浏览器命令支持 `PLAYWRIGHT_MODULE`、`BROWSER_EXECUTABLE` 指定本机工具，属于环境验收入口，不加入缺少Playwright安装的默认确定性CI。

## 验收过程发现与修复

- 发布工具实现者发现JS正则末尾 `$` 可接受换行，候选版本号、source SHA和加载器描述均加严格约束；测试保留原始非法版本/SHA/摘要反例。
- 父Agent审阅发现核心部分执行失败后不能选择恢复版本。加载器改为仅预下载/保存再重载，当前iframe依旧不再次执行核心；独立测试覆盖副作用警告、一次执行、选版保存和重载。

## 测试资产收口与剩余门禁

三个入口分别保留为候选准备、分发和加载器的长期主要责任测试，无平行acceptance副本。测试索引由父Agent统一维护。

浏览器fixture加载的是完整生产加载器与独立小核心ES模块，未冒充完整生产核心及真实酒馆验收。生产核心关于页、真实任务与加载器桥接需在实际宿主验证；真实GitHub提交、jsDelivr可达性/缓存/跨源生产依赖、宿主重载生命周期仍为外部门禁。没有正式发布任何版本。
