# MVU 助手 UI 双视角审阅

- 状态：审阅已完成；用户已授权直接实施，后续见 [UI高标准重构](./2026-10-17-MVU助手UI高标准重构.md)。
- 目标：由玩家与专业产品设计师两个独立角色审阅当前 MVU 助手，生成有证据的问题报告及高标准 UI 重构要求。
- 范围：整体窗口、导航、任务配置、API/预设、世界书/正则、运行反馈、变量编辑与版本更新；本任务交付审阅与重构方案，实施由后续任务承接。
- 设计边界：保留现行独立任务内核与已恢复产品能力；建议不自动成为已批准的产品事实，不将源码推断写成宿主实测。
- 分工：玩家 Agent 独立审阅操作路径、认知负担与错误恢复；产品设计师 Agent 独立审阅信息架构、视觉层级、交互系统、响应式与可访问性；root 审核证据、消除重复、生成综合报告并维护索引。
- 验收：问题包含入口、证据、用户影响、优先级、整改与可验证标准；给出目标信息架构、关键流程、分阶段重构与验收门禁；明确实际浏览器与宿主验证边界。
- 验证所有权：两个角色各自核实其发现，root 核对关键源码证据及报告链接；文档审阅不新增业务测试。
- 文档更新：本任务、综合问题报告与 AI2AI 索引；未决设计不写入稳定架构契约。
- 旧机制取缔：审阅阶段不执行代码取缔。

## 完成记录

- 玩家与产品设计师两个子 Agent 分别交付10项与15项独立发现；root交叉核对后形成15类综合问题及分阶段重构、验收要求，见 [综合报告](../调研/2026-10-17-MVU助手UI问题报告与重构要求.md)。
- root 使用实际 Layout+TaskManager SFC 模拟宿主复现1024×600、768×600的750px面板裁切，稳定截图和尺寸证据随报告保存。
- 已区分源码风险、历史截图、本轮浏览器证据与实际酒馆宿主缺口。未进行真人玩家测试，不将审阅当成真实用户研究。
