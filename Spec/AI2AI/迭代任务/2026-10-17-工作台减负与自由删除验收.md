## 确定性正式验收

内核实现角色交付后运行以下既有入口，三者全部通过：

```powershell
node tests/async-tasks/configuration.cjs
node tests/async-tasks/generation.cjs
node tests/async-tasks/runtime.cjs
```

- configuration：原阻止保存正则/引用完整性断言改为允许编辑；空名称/地址/模型/绑定/坏正则/未完成输出保存重载及 JSON 往返；6 任务引用 API/预设删除后保留任务与组，清空对应引用；任务删除仅去组引用、活动组删除只清选择；共用密钥保留、末使用方删除后清理、持久化失败保留旧快照和密钥。原版本 1 升级、稳定 ID/组结构拒绝、其他模块与正则库隔离、密钥命名空间与损坏错误仍通过。
- generation：14 个未完成配置反例可结构化保存，但选中运行时在 prepare 明确失败，全部 HTTP（包括分词）计数为 0：缺/悬空 API、空模型、空/坏地址、地址嵌入凭据、缺/悬空预设、坏预算、坏任务正则/flags、坏候选正则、坏提取正则、空写入清单；闲置坏任务/API/预设不阻健康任务准备。原并发隔离、预设绑定快照、扫描/模板/预算与取消回归通过。
- runtime：从真实 runTaskChain 入口逐一证明缺 API/model/baseUrl/preset/非法 response 正则失败，具体错误阶段为 prepare，所有 HTTP 为 0；同环境未选择的坏任务不阻健康事件，重绑正常 API 并修正正则后恢复；常规链仅选择健康任务时不被闲置坏资源阻拦。原 busy、取消、间隔、部分成功、重试、回滚、换聊天和重载边界通过。

本轮未改提交/锁/手工变量责任层，commit 与 mvu-editing 沿用上一轮仍有效的独立证据，没有为形式重复执行。

协调角色发现并退回了额外阻拦：密钥数据损坏或孤立密钥清理失败会阻止配置保存。最终独立补充反例并通过：损坏 secret JSON、localStorage.setItem 抛错都不再阻止配置保存/删除，store 暴露“配置已保存，本地密钥清理未完成”警告；后续正常清理消除旧警告。真实 getSecret 遇损坏仍明确抛错，没有静默使用另一方密钥。
