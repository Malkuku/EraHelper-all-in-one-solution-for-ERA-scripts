# 广播作为处理后写入目标

状态：本地实现与独立验收完成，待真实宿主验收。

## 目标与设计

用户明确纠正：事件广播是结果处理后的交付目标，和正文、世界书平级；此前独立 return/event_result 模式是实现与需求偏差。

- 配置版本 4，任务 output 唯一表示为 `{ writes: WriteSpec[] }`，移除 mode。目标新增 `{ kind: 'event' }`；事件写入含 id、target、extract，文本目标保留 operation。每个目标均消费响应阶段正则处理后的文本和本目标提取结果；广播不做正文/MVU写入，不执行针对已有持久文本的追加/替换。
- 用户进一步明确：广播频道固定为任务原触发事件名 + `:output`，不得增加第二份频道配置。广播目标要求任务已填写合法附加事件名；普通常规入口也沿此名称派生。派生频道不得撞本配置其他任务的触发事件名，避免递归。未完成配置允许保存，相关任务准备阶段明确失败。
- 广播成功载荷版本 1，含运行时 scriptId、runId、requestId、taskId、writeId、chatId、messageId、swipeId 与处理后的 text。接收方只需监听原事件名 + `:output`，不需要把安装实例脚本 ID 或任务 ID 硬编码进前端。
- 常规链只在整链成功且写入和状态提交完成后交付广播；后续失败/取消/回滚不发送虚假成功。事件任务按既有独立结算语义交付。广播监听器失败不得重试付费生成，需在运行结果明确报告交付失败/可能部分送达；已交付广播无法撤回，重算可能再次交付，载荷标识用于去重。
- 既有 `${triggerEvent}:result` / `kat_task_chain:result` 保留为运行状态协议，与显式广播写入不是同一业务职责；UI不再把它们当广播目标。TaskResult.text 仅为诊断原文/处理后完整响应，不作为另一种输出模式。
- 联动提示词改为固定通用协议说明，以占位事件名说明配置、监听、生命周期及处理结果，零脚本ID/任务ID固化；在广播目标旁预览/复制。
- v1/2/3输入仍在唯一 parseTaskSettings 边界升级：正常 writes 保留；错误的 return/event_result 转为空 writes 待用户明确目标，不猜测缺失的任务事件名、不静默丢弃旧配置运行。UI及准备错误明确要求补选目标。版本4为唯一内部模型。

## 旧机制取缔

- 删除 return/event_result 模式、生产条件判断、界面选项及依赖其语义的旧测试和稳定描述。
- 删除实例身份插值的旧联动提示词生成逻辑。通用说明不再依赖 getScriptId 或当前触发事件名。

## 分工与测试所有权

- 核心实现 Agent：schema/升级/准备校验/处理提取/广播交付/运行调度与回滚/结果类型，及既有 configuration/generation/commit/runtime suites 的必要适配和最小自测。
- UI实现 Agent：TaskManager、AsyncAnalyze、PromptTools、EventIntegrationRules，含目标编辑与通用说明；不写核心与稳定测试。
- 主 Agent：定界、契约/指南/索引收口、生产App fixture集成与原始截图入口验证、交付审阅。
- 独立验收 Agent：核心稳定后从本任务验收点独立推导风险并沿既有 suites 验证/补缺，不建立平行业务suite。

## 验收与验证范围

- 用户截图“目标”包含事件广播；没有“仅返回结果”或独立广播模式；支持同任务多个混合目标。
- 响应正则及广播提取均实际作用于消费者收到的text，提取失败不广播、关键配置错误零HTTP。
- 常规入口与事件入口都可广播；广播接收名固定派生为任务事件名 + `:output`，混合写入中后续失败、状态保存失败、取消和整链回滚不交付成功结果。
- 明确关联元数据、不同脚本实例运行身份、同一事件多目标区别、监听失败不付费重试且显式报告；不发送密钥。
- 复制通用提示词在不同任务/实例内容一致，不嵌入固定ID或示例实际频道；广播目标和提取规则的保存重载/旧配置升级通过。
- 复用四个稳定 suite、生产App浏览器模拟宿主、定向ESLint与生产构建；真实酒馆跨iframe事件仍须现场验收。
