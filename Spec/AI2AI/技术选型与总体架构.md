# 技术选型与总体架构

## 运行模型

仓库使用 pnpm、TypeScript、Webpack、Vue 3、Pinia 与 Vue Router。Webpack 扫描 `src/**/index.ts` 等入口；`src/MVU助手/index.ts` 导入 UI 和按钮，因此 MVU 助手作为酒馆助手脚本运行。宿主的 `eventOn`、变量、消息、世界书及 `Mvu` 全局 API 是运行前提，接口类型位于 `@types`。

## 模块边界

| 模块 | 当前职责 | 主要源码 |
| --- | --- | --- |
| 入口与 UI | 挂载 Vue 应用、注册按钮和宿主事件、页面导航 | `src/MVU助手/index.ts`、`button.ts`、`UI/` |
| 分步分析 | 根据活动规则组选择任务、控制触发、生成、过滤世界书、合并结果和回滚 | `src/MVU助手/AsyncAnalyze/` |
| 配置状态 | 保存任务组、任务池、API 配置、备份、UI 偏好 | `src/MVU助手/stores/` |
| MVU 桥接 | 解析消息更新、覆盖当前消息 MVU 数据、滑动消息时回退 | `src/Utils/MvuUtil.ts` |
| 版本更新 | 从世界书解析版本块、预览差异、更新 `stat_data` | `src/MVU助手/stores/UseVersionControlStore.ts` |
| 宿主适配 | 世界书、消息、正则、提示词和模型 API 封装 | `src/Utils/` |

## 关键数据流

1. 脚本初始化时创建 Vue/Pinia 实例，读取分步分析与版本配置，注册消息、世界书和重算事件。
2. `MESSAGE_SENT` 处理负 `order` 任务并等待完成；`MESSAGE_RECEIVED` 启动非负 `order` 任务；自定义事件可触发对应任务。任务按 `order` 分组，组内发起多个任务，模型生成环节通过锁串行。
3. 任务结果按合并配置写入消息或世界书。旧版变量标签可转换为 `<UpdateVariable><JSONPatch>`；消息内容经 `MvuUtil` 调用 `Mvu.parseMessage` 和 `Mvu.replaceMvuData` 更新变量。
4. 数据编辑与版本更新经 `MvuUtil.updateMvuDataByObj` 覆盖当前消息的 `stat_data`。分步任务在执行前备份消息、世界书条目和触发历史，错误时尝试回滚。

## 已移除机制与文档状态

- EraDataRule/DSL 规则引擎已被移除。当前仓库无 `src/MVU助手/EraDataHandler/`，路由也没有规则编辑页。`src/MVU助手/doc/` 中相关指南、图和样例属于历史资料，不是现行 API 契约。
- 版本更新设置仍使用历史键名 `era_data_rule.version_control`；它只承载版本更新配置，不能作为 EraDataRule 仍存在的证据。改名涉及已有脚本变量的迁移，应另行处理。
- 旧 EraDataRule 文档中的 `kat:handle_era_finished` 不是现行完成事件。现存分步分析服务发出 `kat_handle_mvu_finished`，见分步分析契约。
- `src/MVU助手/doc/关于分步分析的补充.md` 的图片路径仍含旧 `src/ERA助手` 名称；文档内容可供理解历史设计，但不作为独立现行契约。
