# 编写 Skill

## 流程

1. **收集需求**，确认：
   - 这个 skill 覆盖什么任务或领域？
   - 它需要处理哪些具体用例？
   - 它只需要文字指令，还是需要可执行脚本？
   - 是否需要附带参考资料、示例或模板？

2. **起草 skill**，创建：
   - 简洁的 `SKILL.md`
   - 如果主体内容过长，拆出参考文件
   - 如果存在确定性、可复用操作，加入工具脚本

3. **和用户复核**，确认：
   - 是否覆盖目标用例？
   - 是否有遗漏或含糊的规则？
   - 哪些部分需要增加或减少细节？

## 目录结构

```text
skill-name/
├── SKILL.md           # 主说明文件，必需
├── REFERENCE.md       # 详细参考资料，按需添加
├── EXAMPLES.md        # 使用示例，按需添加
└── scripts/           # 工具脚本，按需添加
    └── helper.js
```

## SKILL.md 模板

```md
---
name: skill-name
description: 简要说明这个 skill 的能力。Use when [明确触发场景]。
---

# Skill Name

## 快速开始

[最小可用示例]

## 工作流

[复杂任务的分步流程和检查清单]

## 进阶内容

[链接到拆分文件，例如：See [REFERENCE.md](REFERENCE.md)]
```

## Description 要求

`description` 是 agent 决定是否加载 skill 时最重要的信息。

它需要让 agent 快速判断：

1. 这个 skill 提供什么能力。
2. 什么时候、为什么应该触发它。

格式要求：

- 不超过 1024 字符
- 使用第三人称描述能力
- 第一句说明能力
- 第二句使用 `Use when ...` 说明触发场景

好例子：

```text
从 PDF 文件中提取文本和表格，填写表单，合并文档。Use when 处理 PDF 文件，或用户提到 PDF、表单、文档提取。
```

坏例子：

```text
帮助处理文档。
```

坏例子太宽泛，agent 无法把它和其他文档类 skill 区分开。

## 什么时候添加脚本

在以下情况添加工具脚本：

- 操作是确定性的，例如校验、格式化、生成固定结构
- 同一段代码可能被反复生成
- 错误处理需要明确、稳定

脚本能减少重复生成代码的成本，也能提高可靠性。

## 什么时候拆分文件

在以下情况拆分额外文件：

- `SKILL.md` 超过 100 行
- 内容包含彼此独立的领域
- 进阶内容不常用，只应按需加载

## 复核清单

起草完成后检查：

- [ ] `description` 包含明确触发条件，也就是 `Use when...`
- [ ] `SKILL.md` 控制在 100 行以内
- [ ] 没有容易过期的时效性信息
- [ ] 术语前后一致
- [ ] 包含具体示例
- [ ] 引用文件只保持一层深度
